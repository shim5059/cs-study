## 1. DB에 저장되는 건 "정보"가 아니라 "데이터"

### 처음 생각 (오답)
데이터와 정보를 비슷한 말로 섞어 썼고, 정의를 쓸 때 키워드(관찰·측정 / 의사 결정·처리)가 빠졌다. DB에 정보가 저장된다고 썼다.

### 원리
```
 관찰·측정          처리               의사 결정
현실 ───────▶ [데이터] ───────▶ [정보] ───────▶ 행동
              21, 23, 19        "평균 21도,        겉옷을 챙김
              (DB에 저장)        겉옷 필요"
```
DB는 가공 전 재료인 **데이터**를 저장하고, 정보는 그 데이터를 꺼내 처리한 **결과**다.

### 깨달음
- 데이터 = **관찰·측정**한 값 / 정보 = **의사 결정**에 쓰도록 **처리**한 결과
- 서술형은 이 키워드가 들어가야 점수가 된다

## 2. 통제된 중복을 허용하는 이유

### 처음 생각 (오답)
"통합 데이터 = 중복이 전혀 없음"으로 이해해서, 중복을 일부 허용하는 이유(백업·성능)를 대지 못했다. 시험 직전 복습에서도 **다시** 틀렸다.

### 원리
```
중복 0%  ──────────────────────────  중복 많음
 (이상)         ▲ 통제된 중복          (파일 시스템의 문제)
                │
     일부러 남기는 중복: 백업본, 자주 쓰는 값 복사본
```
- **백업**: 장애가 나도 복구할 수 있게
- **성능**: 매번 여러 곳을 찾지 않고 빠르게 읽게

### 깨달음
통합 데이터는 "중복 **최소화**"이지 "중복 0"이 아니다. 허용 이유는 **백업·성능** 두 단어로 기억한다.

## 3. "여러 사용자가 동시에" = 동시 공유 (실시간 접근 아님)

### 처음 생각 (오답)
"여러 사용자가 동시에 이용"을 **실시간 접근**으로 골랐다. 특징을 쓸 때도 "동시에"를 빠뜨리고 "공유"만 썼다.

### 원리

| 특징 | 핵심 단어 | 질문 |
|---|---|---|
| 실시간 접근 | **바로** 응답 | 얼마나 빨리? |
| 동시 공유 | **여러 명이 동시에** | 몇 명이 같이? |
| 계속적인 변화 | 삽입·삭제·수정 | 내용이 바뀌나? |
| 내용 기반 참조 | 주소가 아니라 값 | 무엇으로 찾나? |

또 "공유 데이터"(정의 키워드)와 "동시 공유"(특징)는 서로 다른 목록이다.

### 깨달음
문장에 **"동시에"**가 있으면 동시 공유, **"즉시/바로"**가 있으면 실시간 접근.

## 4. 반정형 = 구조 정보를 데이터와 **같이** 가진 것

### 처음 생각 (오답)
반정형을 "미리 정해진 구조가 있는 데이터"로 설명했다. 그건 정형 데이터의 설명이다.

### 원리
```
정형 (표, 구조가 밖에 따로 있음)        반정형 (구조 정보가 값 옆에 붙어 있음)
┌────────┬──────┐                     { "이름": "민준",
│ 이름    │ 나이 │  ← 구조(스키마)          "나이": 23 }
├────────┼──────┤                       ▲ 이름표("이름","나이")가
│ 민준    │ 23   │  ← 값                    값과 같이 저장됨
└────────┴──────┘
```

### 깨달음
반정형 = "**구조를 표현하는 정보가 데이터와 함께** 존재" (HTML, XML, JSON).

## 5. 이산형 vs 연속형을 반대로

### 처음 생각 (오답)
이산형과 연속형의 뜻을 거꾸로 이해해서 **체온을 이산형**으로 분류했다. (시험 직전 복습에서 **다시** 틀렸고, 오답노트 재시험에서 맞힘)

### 원리
```
이산형: 셀 수 있음 (사이 값이 없음)
  방문자 수  ●   ●   ●   ●        12명, 13명 … 12.5명은 없음
            12  13  14  15

연속형: 잴 수 있음 (사이 값이 무한)
  체온      ━━━━━━━━━━━━━━━━━━    36.5, 36.51, 36.512 …
           36.0            37.0
```

### 깨달음
"**몇 개/몇 명?**" → 이산형, "**얼마나(재는 값)?**" → 연속형. 학번은 숫자지만 계산하지 않는 이름표라서 **명목형**.

## 6. 데이터 종속성 vs 데이터 중복성

### 처음 생각 (오답)
종속성을 중복성과 헷갈렸다. "중복성 문제가 **아닌** 것"을 고르는 문제에서는 "보안·무결성 유지가 어려움"(이건 중복성 문제가 맞다)을 골랐다.

### 원리
```
중복성: 같은 데이터가 여러 파일에
  [수강 파일: 민준, 010-1111]   [장학 파일: 민준, 010-1111]
   → 한쪽만 고치면 불일치, 두 곳 다 지켜야 해서 보안·무결성 관리가 어려움

종속성: 프로그램이 파일 구조에 묶임
  프로그램 ──읽기──▶ [이름(10칸)|전화(13칸)]
   → 칸 구조를 바꾸면 프로그램도 고쳐야 함
```

| 문제 | 원인 | 결과 |
|---|---|---|
| 중복성 | 같은 데이터가 **여러 곳** | 불일치, 보안·무결성 유지 어려움, 공간 낭비 |
| 종속성 | 프로그램이 **파일 구조**에 묶임 | 구조 변경 → 프로그램 수정 |

### 깨달음
"구조를 바꾸면 프로그램을 고쳐야 한다" = **종속성**. 종속성을 해결한 결과가 **데이터 독립성**이다.

## 7. DBMS 제어 기능의 4가지 역할

### 처음 생각 (오답)
- 제어 기능의 역할을 물었는데 **명령어**(GRANT 등)로 답했다.
- "재고 1개 남은 상품을 두 사람이 동시에 주문" 상황을 **무결성**으로 골랐다. 동시성 제어를 언제 배웠는지도 기억나지 않았다.

### 원리
제어 기능은 **역할 4가지**로 쓴다.
```
제어 기능
 ├─ 무결성 : 정확하고 올바른 값만 유지     (나이에 -5 금지)
 ├─ 보안·권한 : 허가된 사용자만 접근        (학생은 성적 수정 불가)
 ├─ 동시성 제어 : 동시에 써도 결과가 꼬이지 않게 (재고 1개를 둘이 동시 주문)
 └─ 회복 : 장애가 나도 일관된 상태로 복구    (정전 후 복구)
```

### 깨달음
"동시에 여러 사용자"가 나오면 **동시성 제어**. 이 내용은 8주차(10장 병행 제어)에서 다시 나온다.

## 8. 사상과 스키마 이름: "물리"가 아니라 "내부"

### 처음 생각 (오답)
- 논리적·물리적 데이터 독립성을 쓸 때 관련 **사상** 이름을 빠뜨렸다.
- "물리 스키마", "개념/물리 사상"이라고 썼다.

### 원리
```
외부 스키마
    │  외부/개념 사상  →  논리적 데이터 독립성
개념 스키마
    │  개념/내부 사상  →  물리적 데이터 독립성
내부 스키마   ← 이름은 "내부". "물리적"은 독립성 이름에만 붙음
```

### 깨달음
스키마 이름은 **외부·개념·내부**, 독립성 이름은 **논리적·물리적**. 섞어 쓰지 않는다.

## 9. 개념 스키마 ⊂ 메타데이터 (포함 관계를 거꾸로)

### 처음 생각 (오답)
메타데이터가 개념 스키마 안에 들어 있다고 거꾸로 생각했다. (시험 직전 복습에서 다시 틀리고, 오답노트 재시험에서 맞힘)

### 원리
```
┌──────── 데이터 사전 (메타데이터 전체) ────────┐
│  사용자 정보 · 권한 · 인덱스 · 뷰 · 통계        │
│  ┌──────────────────────────────┐            │
│  │ 3단계 스키마 (외부·개념·내부)  │            │
│  └──────────────────────────────┘            │
└──────────────────────────────────────────────┘
```

### 깨달음
데이터 사전이 **큰 상자**, 스키마는 그 안에 저장되는 메타데이터 **중 하나**.

## 10. 저장 데이터 관리자 vs 질의 처리기

### 처음 생각 (오답)
디스크의 DB와 데이터 사전을 관리하는 역할을 **질의 처리기**로 골랐다.

### 원리
```
사용자 요청 ──▶ [질의 처리기]  요청을 해석·번역
                     │
                     ▼
              [저장 데이터 관리자]  실제로 디스크에 접근
                     │
                     ▼
              디스크: DB + 데이터 사전
```

### 깨달음
**해석**하는 쪽 = 질의 처리기, **디스크를 만지는** 쪽 = 저장 데이터 관리자.

---

## 11. 절차적 DML vs 비절차적 DML

### 처음 생각 (오답)
두 종류의 차이를 몰라서 답을 쓰지 못했다.

### 원리
```
절차적    : "고객 표를 처음부터 한 줄씩 읽어서, 등급이 gold면 이름을 출력해"  (무엇 + 어떻게)
비절차적  : SELECT 고객이름 FROM 고객 WHERE 등급 = 'gold';              (무엇만)
```

### 깨달음
**어떻게**까지 말하면 절차적, **무엇만** 말하면 비절차적. SQL은 비절차적이다. (6장에서 관계 대수=절차적, 관계 해석=비절차적으로 같은 구분이 다시 나온다)

## 정리

| 착각 | 바로잡은 규칙 |
|---|---|
| DB에 정보가 저장됨 | DB에는 **데이터**, 정보는 처리한 결과 |
| 통합 = 중복 0 | 중복 **최소화**, 통제된 중복은 **백업·성능** 때문 |
| "동시에" = 실시간 접근 | "동시에" = **동시 공유** |
| 반정형 = 정해진 구조 | 구조 정보가 **데이터와 함께** |
| 체온 = 이산형 | 셀 수 있으면 이산, **잴 수 있으면 연속** |
| 종속성 = 중복성 | 종속성 = 프로그램이 **파일 구조**에 묶임 |
| 제어 기능 = 명령어 | **무결성·보안/권한·동시성 제어·회복** |
| 동시 주문 = 무결성 | 동시 주문 = **동시성 제어** |
| 물리 스키마, 개념/물리 사상 | **내부** 스키마, **개념/내부** 사상 |
| 메타데이터 ⊂ 개념 스키마 | **개념 스키마 ⊂ 메타데이터** |
| 디스크 관리 = 질의 처리기 | 디스크 관리 = **저장 데이터 관리자** |
| 절차적/비절차적 구분 모름 | 어떻게까지 = 절차적, 무엇만 = 비절차적 |
