## 1. 데이터 vs 정보

| | 정의 | 키워드 |
|---|---|---|
| 데이터 | 현실 세계에서 단순히 **관찰·측정**해 수집한 사실이나 값 | 관찰, 측정 |
| 정보 | 데이터를 **의사 결정**에 유용하게 쓰도록 **처리**해 체계적으로 조직한 결과물 | 의사 결정, 처리 |

- DB에 저장되는 것은 **데이터**다 (정보는 처리 결과)
- 예: 매일 기록한 기온 `21, 23, 19` = 데이터 → "이번 주 평균 21도, 겉옷 필요" = 정보

## 2. 데이터베이스의 정의와 특징

**정의 (4가지 데이터)**: 여러 사용자가 **공유**할 목적으로, 중복을 최소화해 **통합**하고, 컴퓨터가 접근할 수 있는 매체에 **저장**한, 조직의 업무 수행에 꼭 필요한 **운영** 데이터

| 정의 키워드 | 뜻 |
|---|---|
| 공유 데이터 | 여러 사용자가 함께 쓰는 데이터 |
| 통합 데이터 | 중복을 최소화한 데이터 (단, **통제된 중복**은 허용) |
| 저장 데이터 | 컴퓨터가 접근할 수 있는 매체에 저장 |
| 운영 데이터 | 조직의 업무에 꼭 필요한 데이터 |

- 통제된 중복을 허용하는 이유: **백업**(장애 대비)과 **성능**(검색 속도)

**특징 4가지**

| 특징 | 뜻 |
|---|---|
| 실시간 접근 | 질의에 바로(수 초 내) 응답 |
| 계속적인 변화 | **삽입·삭제·수정**으로 늘 최신 상태 유지 |
| 동시 공유 | 여러 사용자가 **동시에** 같은 데이터를 이용 |
| 내용 기반 참조 | 주소가 아니라 **값(내용)**으로 데이터를 찾음 |

## 3. 데이터 분류

**형태에 따라**

| 분류 | 뜻 | 예 |
|---|---|---|
| 정형 | 미리 정해진 구조(표)에 맞춰 저장 | 엑셀 표, 관계 DB 테이블 |
| 반정형 | 구조가 있지만 **구조 정보를 데이터와 함께** 저장 | HTML, XML, JSON |
| 비정형 | 정해진 구조가 없음 | 글, 영상, 이미지, 음성 |

```json
{ "이름": "민준", "나이": 23 }   ← "이름", "나이"라는 구조 정보가 값과 같이 들어 있음 (반정형)
```

**특성에 따라**

| 큰 분류 | 작은 분류 | 기준 | 예 |
|---|---|---|---|
| 범주형 | 명목형 | 순서 없음 | 성별, 혈액형, 학번 |
| | 순서형 | 순서 있음 | 학년, 만족도(상·중·하) |
| 수치형 | 이산형 | **셀 수 있는** 값 (정수) | 고객 수, 방문자 수, 판매량 |
| | 연속형 | **잴 수 있는** 값 (중간값 무한) | 키, 몸무게, 체온 |

## 4. 파일 시스템의 문제 → DBMS 등장

| 문제 | 뜻 |
|---|---|
| 데이터 중복성 | 같은 데이터가 여러 파일에 저장 → 불일치, 보안·무결성 유지 어려움, 저장 공간 낭비 |
| 데이터 종속성 | 응용 프로그램이 **파일 구조**에 묶여 있음 → 파일 구조가 바뀌면 프로그램도 고쳐야 함 |

## 5. DBMS 3가지 기능

| 기능 | 하는 일 | 언어 |
|---|---|---|
| 정의 기능 | 데이터 **구조**를 정의하고 **수정**·삭제 | DDL |
| 조작 기능 | 데이터 **삽입·삭제·수정·검색** | DML |
| 제어 기능 | **무결성** 유지, **보안·권한** 검사, **동시성 제어**(병행 제어), 장애 시 **회복** | DCL |

## 6. 스키마와 인스턴스

| | 뜻 | 변하는 정도 | 다루는 언어 |
|---|---|---|---|
| 스키마 | DB에 저장되는 데이터의 **구조와 제약조건**을 정의한 것 | 거의 안 바뀜 | DDL |
| 인스턴스 | 스키마에 따라 **특정 시점**에 실제로 저장된 값 | 자주 바뀜 (계속적인 변화) | DML |

```
스키마    고객(고객아이디, 고객이름, 나이)         ← 틀
인스턴스  ('cat', '김민준', 23), ('dog', '이서연', 31) ← 지금 들어 있는 값
```

## 7. 3단계 데이터베이스 구조 (ANSI/SPARC)

```
 사용자1    사용자2    사용자3
   │          │          │
[외부 스키마][외부 스키마][외부 스키마]   개별 사용자 관점 · 여러 개 · 서브 스키마
        \       │       /
         외부/개념 사상  ─────────────  논리적 데이터 독립성
               │
         [ 개념 스키마 ]              조직 전체 관점 · 1개
               │
         개념/내부 사상  ─────────────  물리적 데이터 독립성
               │
         [ 내부 스키마 ]              물리적 저장 장치 관점 · 1개
               │
            디스크
```

- **논리적 데이터 독립성**: 개념 스키마가 바뀌어도 외부 스키마는 영향 없음 (외부/개념 사상만 고침)
- **물리적 데이터 독립성**: 내부 스키마가 바뀌어도 개념 스키마는 영향 없음 (개념/내부 사상만 고침)
- 3단계로 나누는 이유: **데이터 독립성**을 실현하려고

## 8. 데이터 사전 (= 시스템 카탈로그)

- DB에 저장된 데이터를 정확하고 효율적으로 쓰기 위한 정보(**메타데이터**, 데이터에 관한 데이터)를 저장
- 테이블·사용자·인덱스·뷰 정보 등, 3단계 스키마 정보도 여기에 저장 → **개념 스키마 ⊂ 메타데이터**
- 시스템 DB라고도 부르고, DBMS가 관리 → 사용자는 **읽기만** 가능
- 데이터 디렉터리: 데이터 사전의 데이터에 실제로 접근하는 데 필요한 위치 정보 (시스템만 접근)

## 9. 데이터 언어

| 언어 | 용도 | 명령어 (7장) |
|---|---|---|
| DDL (정의어) | 스키마 정의·수정·삭제 | `CREATE`, `ALTER`, `DROP` |
| DML (조작어) | 데이터 삽입·삭제·수정·검색 | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| DCL (제어어) | 무결성·보안·권한·회복 등 제어 | `GRANT`, `REVOKE`, `COMMIT`, `ROLLBACK` |

**DML의 두 종류**

| | 사용자가 명시하는 것 |
|---|---|
| 절차적 DML | **어떤** 데이터가 필요하고 **어떻게** 처리할지 |
| 비절차적 DML | **어떤** 데이터가 필요한지만 (SQL이 대표적) |

## 10. DBMS 구성 (질의 처리기 · 저장 데이터 관리자)

| 구성 요소 | 역할 |
|---|---|
| 질의 처리기 | 사용자 요청(질의)을 해석해 처리 (DDL 컴파일러, DML 프리 컴파일러, DML 컴파일러, 런타임 DB 처리기, 트랜잭션 관리자) |
| 저장 데이터 관리자 | 디스크에 있는 **DB와 데이터 사전**을 관리하고 실제로 접근 |

- 응용 프로그래머가 쓴 프로그램 속 DML 흐름: **DML 프리 컴파일러**(DML을 따로 추출) → **DML 컴파일러** → 런타임 DB 처리기 → 저장 데이터 관리자
