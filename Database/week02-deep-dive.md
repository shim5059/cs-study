## 1. 데이터 모델 3요소에 "관계"는 없다

### 처음 생각 (오답)
"데이터 모델 3요소가 **아닌** 것"을 고르는 문제에서 처음엔 **연산**을, 오답노트 재시험에서는 **제약조건**을 골랐다. 정답은 **관계**. ERD의 재료(개체·속성·관계)와 섞였다.

### 원리
```
데이터 모델 3요소           ERD의 재료
┌──────────────┐          ┌──────────────┐
│ 데이터 구조   │          │ 개체          │
│ 연산         │    ≠     │ 속성          │
│ 제약조건      │          │ 관계          │
└──────────────┘          └──────────────┘
 "모델이 갖춰야 할 것"       "그림에 그리는 것"
```
- 구조 = 어떻게 **담나** / 연산 = 어떻게 **다루나** / 제약조건 = 무엇을 **막나**

### 깨달음
3요소는 **구·연·제**(구조·연산·제약조건). "관계"가 보이면 ERD 쪽 목록이다.

## 2. 데이터 모델링 정의와 E-R 모델 vs E-R 다이어그램

### 처음 생각 (오답)
데이터 모델링 정의에 핵심 키워드(현실 세계 → 컴퓨터 세계 DB, **변환 과정**)가 빠졌고, E-R 모델과 E-R 다이어그램을 같은 것으로 썼다.

### 원리
```
현실 세계 ───────(변환 과정 = 데이터 모델링)───────▶ 컴퓨터 세계의 DB

E-R 모델       : 그리는 "방법"   (설계도 그리는 규칙)
E-R 다이어그램  : 그린 "결과물"   (완성된 설계도)
```

### 깨달음
모델링은 **과정**, ERD는 **결과물**. 서술형에는 "현실 세계 → 컴퓨터 세계"와 "변환 과정"을 꼭 쓴다.

## 3. 모델 → 스키마 → 인스턴스 순서

### 처음 생각 (오답)
셋의 순서를 묻는 문제를 틀렸고, 재시험에서도 확신 없이 골랐다.

### 원리
```
데이터 모델   "표로 저장한다"                 ← 규칙 (가장 추상)
    ▼
스키마        고객(고객아이디, 고객이름, 나이)   ← 그 규칙으로 만든 틀
    ▼
인스턴스      ('cat', '김민준', 23)            ← 틀에 들어간 실제 값
```

### 깨달음
**규칙 → 틀 → 값** 순서. 추상적인 것에서 구체적인 것으로 내려간다.

---

## 4. 속성 기호: 점선 타원 = 유도, 밑줄 = 키

### 처음 생각 (오답)
- **점선 타원**(유도 속성)을 **복합** 속성으로 골랐다.
- ERD를 그릴 때 키 속성에 **점선**을 쓰려 했다.

### 원리
```
  (학번)      키 속성: 이름에 실선 밑줄
  ((연락처))   다중 값: 이중 타원
  (주소)─┬─(시)  복합: 작은 타원이 가지처럼
        └─(구)
  ( 나이 )    유도: 점선 타원 (생년월일로 계산)
  ‥‥‥‥‥
```
- "나이를 생년월일로 계산" → 나이를 **점선 타원**으로 그리고 회원에 **직접** 연결한다 (생년월일에 매달지 않음)

### 깨달음
**점선 = 계산해서 나오는 것(유도)**, **가지 = 쪼개지는 것(복합)**, **밑줄 = 구별하는 것(키)**.

## 5. 개체 vs 속성 구분

### 처음 생각 (오답)
학번과 나이를 **개체**로 생각했다.

### 원리
```
개체: 따로 저장할 가치가 있고, 스스로 여러 속성을 가지는 "대상"
       [학생] ── 학번, 이름, 나이 …

속성: 개체를 "설명하는 값" 하나
       학번 → 학생을 설명
       나이 → 학생을 설명
```
판별 질문: "이것도 자기만의 속성을 여러 개 가지나?" → 아니면 속성.

### 깨달음
학번·나이·이름은 **학생을 설명하는 값**이라 속성이다.

---

## 6. 이중 사각형 = 약한 개체, 이중선 = 필수 참여

### 처음 생각 (오답)
이중 사각형을 **필수 참여**로 읽었다. (4장 연습문제와 오답노트 재시험에서 **두 번** 틀림)

### 원리
```
[사원] ══════ <<부양>> ══════ [[부양가족]]
   ▲             ▲              ▲
 일반 개체    이중 마름모       이중 사각형 = 약한 개체
             (식별 관계)
                    ══ 이중선 = 필수 참여
```
| 이중으로 그린 것 | 뜻 |
|---|---|
| 사각형 | 약한 개체 |
| 마름모 | 약한 개체를 식별하는 관계 |
| **선** | 필수 참여 |
| 타원 | 다중 값 속성 |

약한 개체는 주인 없이 존재할 수 없으니 **항상 필수 참여(이중선)**다.

### 깨달음
**도형**이 이중이면 그 도형의 종류가 특별하다는 뜻, **선**이 이중이면 참여가 필수라는 뜻.

## 7. 매핑 카디널리티 읽기

### 처음 생각 (오답)
- 정의를 정확히 쓰지 못했다.
- 양쪽이 모두 "여러"인 관계를 N:M으로 판단하지 못했다.
- ERD에서 1 쪽 개체가 상대를 몇 개 가지는지 거꾸로 읽었다.

### 원리
```
 [부서] 1 ────<소속>──── N [사원]

 사원 한 명 → 부서 1개    (사원 옆이 아니라 "건너편" 숫자를 읽음)
 부서 하나  → 사원 N명
```
"한 학생은 여러 과목, 한 과목은 여러 학생" → 양쪽 다 여러 → **N:M**

### 깨달음
정의: "한 개체 인스턴스가 상대 개체 인스턴스 **몇 개**와 연결되는가". 숫자는 **건너편** 것을 읽는다.

## 8. 시나리오를 ERD로 옮길 때의 규칙

### 처음 생각 (오답)
연습 시나리오로 ERD를 그리며 다음을 틀렸다.
- 관계를 어디서 찾아야 할지 몰랐다
- "반드시"라는 말이 없는데 필수 참여로 그렸다
- 개체의 키(학번 등)를 관계의 속성으로 붙였다
- 여러 개체의 속성을 한곳에 몰아 썼다

### 원리
```
"학생은 여러 과목을 수강한다. 수강할 때 성적을 기록한다."
  명사 → 개체        학생, 과목
  동사 → 관계        수강
  관계에만 생기는 값  성적 → 수강(관계)의 속성
  학번               → 학생(개체)의 키, 관계 속성 아님
  "반드시" 없음       → 선택 참여(단일선)
```

### 깨달음
**명사=개체, 동사=관계, "반드시"=이중선**. 관계 속성은 "그 관계가 일어날 때만 생기는 값"뿐이다.

## 정리

| 착각 | 바로잡은 규칙 |
|---|---|
| 3요소에 관계/연산/제약조건 중 하나를 뺌 | 3요소 = **구조·연산·제약조건**, 관계는 ERD 재료 |
| E-R 모델 = ERD | 모델은 방법, **ERD는 결과물** |
| 모델·스키마·인스턴스 순서 불확실 | **규칙 → 틀 → 값** |
| 점선 타원 = 복합 | 점선 타원 = **유도**, 가지 = 복합 |
| 키에 점선 | 키 = **밑줄** |
| 학번·나이 = 개체 | 개체를 **설명하는 값**이라 속성 |
| 이중 사각형 = 필수 참여 | 이중 사각형 = **약한 개체**, 이중**선** = 필수 참여 |
| 양쪽 여러 → N:M 판단 못 함 | 양쪽 다 여러 = **N:M**, 숫자는 건너편을 읽음 |
| "반드시" 없어도 필수 참여 | "반드시"가 있을 때만 이중선 |
| 개체의 키를 관계 속성으로 | 관계 속성 = 관계가 일어날 때 생기는 값만 |
