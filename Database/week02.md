# 2주차 · 데이터 모델링과 E-R 다이어그램

> 헷갈렸던 부분과 해결 과정: [week02-deep-dive.md](week02-deep-dive.md)

> 교재 4장 · 시험 강조: **데이터 모델 3요소**, **NULL 정의**, **ERD 기본 기호**, 시나리오를 읽고 ERD 그리기

## 1. 데이터 모델링

- **정의**: 현실 세계의 데이터를 컴퓨터 세계의 DB로 옮기는 **변환 과정**

```
현실 세계 ──개념적 모델링──▶ 개념 세계 ──논리적 모델링──▶ 컴퓨터 세계
(실제 학생)    특징 추출·추상화   (E-R 다이어그램)  DB에 맞게 표현   (릴레이션 스키마)
```

| 단계 | 결과 | 대표 모델 |
|---|---|---|
| 개념적 데이터 모델링 | 현실의 중요한 특징만 추출(추상화) | **E-R 모델** → 결과물 **E-R 다이어그램** |
| 논리적 데이터 모델링 | 개념 구조를 DB가 저장할 형태로 | 관계 데이터 모델(테이블), 계층(트리), 네트워크(그래프) |

- E-R **모델** = 방법(이론), E-R **다이어그램(ERD)** = 그 방법으로 그린 결과물

## 2. 데이터 모델의 3요소

| 요소 | 뜻 | 특성 |
|---|---|---|
| 데이터 구조 | 데이터를 어떤 형태로 저장할지 | 정적 |
| 연산 | 저장된 데이터를 처리하는 작업 | 동적 |
| 제약조건 | 데이터 무결성 유지를 위한 규칙 | |

- ⚠ **관계**는 3요소가 아니다 (관계는 ERD의 재료: 개체·속성·관계)
- 순서: **데이터 모델 → 스키마 → 인스턴스** (모델로 스키마를 정의하고, 스키마에 실제 값이 인스턴스)

## 3. 개체 (Entity)

- 현실에서 **저장할 가치가 있는 대상** (사람·사물·사건), 사각형
- 개체 타입: 개체 이름 + 속성들로 정의한 **틀** (예: `학생(학번, 이름, 학과)`)
- 개체 인스턴스: 개체 타입에 따라 실제 값을 가진 **개별 개체 하나** (예: `(2401, 민준, 컴공)`)
- 개체 집합: 개체 인스턴스들의 모음

## 4. 속성 (Attribute)과 기호

| 종류 | 뜻 | 예 | ERD 기호 |
|---|---|---|---|
| 단일 값 | 값이 하나 | 학번 | 타원 |
| 다중 값 | 값이 여러 개 | 연락처(집·휴대폰) | **이중 타원** |
| 단순 | 더 쪼갤 수 없음 | 이름 | 타원 |
| 복합 | 쪼개서 의미 있음 | 주소 → 시, 구 | 타원에 작은 타원이 **가지**로 |
| 유도 | 다른 속성에서 계산 | 나이(← 생년월일) | **점선 타원** |
| 키 | 개체를 구별 | 학번 | 이름에 **밑줄** |

- **NULL**: 아직 지정되지 않았거나 모르는 값. 0이나 공백(빈 문자열)과 **다르다**

## 5. 관계 (Relationship)

- 개체와 개체 사이의 **연관성**, 마름모. 요구사항의 **동사**에서 찾는다 (`학생이 과목을 **수강**한다`)
- 관계도 속성을 가질 수 있다 (수강의 `성적`)
- 같은 두 개체 사이에 관계가 **여러 개** 있을 수 있다 (의사—진료과: `소속`, `관리(과장)`)

**매핑 카디널리티**: 한 개체 인스턴스가 상대 개체 인스턴스 **몇 개**와 연결되는지

| 종류 | 읽는 법 | 예 |
|---|---|---|
| 1:1 | 양쪽 다 최대 하나 | 사원—사물함 |
| 1:N | 한쪽은 여러, 반대쪽은 하나 | 부서(1)—사원(N) |
| N:M | **양쪽 다 여러** | 학생—과목 |

**참여 특성**

| | 뜻 | 기호 |
|---|---|---|
| 필수 참여 | 모든 인스턴스가 반드시 관계에 참여 ("반드시") | **이중선** |
| 선택 참여 | 참여하지 않는 인스턴스도 있음 | 단일선 |

## 6. 약한 개체

- 스스로 키를 못 가져 **주인(오너) 개체**의 키에 기대는 개체: **이중 사각형**
- 주인과 잇는 관계: **이중 마름모**, 약한 개체 쪽은 항상 **필수 참여(이중선)**
- 부분키(주인 안에서만 구별): **점선 밑줄**

```
 [사원]════<<부양>>════[[부양가족]]
 사원번호(밑줄)        이름(점선 밑줄) ← 같은 사원 안에서만 구별
```

## 7. ERD 그리기 순서 (직접 만든 예)

> 요구사항: 회원은 회원번호로 구별하고 이름, 주소(시·구), 연락처(여러 개), 생년월일을 가진다. 나이는 생년월일로 계산한다. 회원은 여러 도서를 대여할 수 있고 한 도서도 여러 회원이 대여할 수 있다. 대여할 때 대여일을 기록한다.

1. **개체** (명사, 저장할 가치): 회원, 도서
2. **속성** (개체를 설명): 회원번호(키), 이름, 주소{시, 구}(복합), 연락처(다중 값), 생년월일, 나이(유도)
3. **관계** (동사): 대여 — 관계 속성 대여일
4. **카디널리티·참여**: "여러 ↔ 여러" → N:M, "반드시"가 없으므로 선택 참여

```
                      대여일
                        │
 [회원] ──N── <대여> ──M── [도서]
  ├ 회원번호(밑줄)            ├ 도서번호(밑줄)
  ├ 이름                      └ 제목
  ├ 주소 ─┬ 시
  │       └ 구
  ├ ((연락처))   ← 이중 타원
  ├ 생년월일
  └ (나이)       ← 점선 타원
```
