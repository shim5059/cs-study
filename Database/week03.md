# 3주차 · 관계 데이터 모델 (릴레이션, 키, 무결성)

> 헷갈렸던 부분과 해결 과정: [week03-deep-dive.md](week03-deep-dive.md)

> 교재 5장 · 시험 강조: **차수 vs 카디널리티**, **릴레이션 4가지 특성**, **키의 종류**, **개체·참조 무결성 제약조건**(최우선), 외래키

## 1. 기본 용어

```
릴레이션 이름: 고객
          속성(열) ───────────────────────▶ 차수 = 속성 개수 = 4
        ┌──────────┬────────┬──────┬────────┐
        │ 고객아이디 │ 고객이름 │ 나이 │ 등급    │  ← 릴레이션 스키마 (머리줄)
        ├──────────┼────────┼──────┼────────┤
투플(행) │ cat      │ 김민준   │ 23   │ gold   │ ┐
   │    │ dog      │ 이서연   │ 31   │ vip    │ ├ 릴레이션 인스턴스
   ▼    │ fox      │ 박도윤   │ NULL │ silver │ ┘
        └──────────┴────────┴──────┴────────┘
        카디널리티 = 투플 개수 = 3 (머리줄은 세지 않음)
```

| 용어 | 뜻 |
|---|---|
| 속성 (애트리뷰트) | 열 하나 (이름이 붙은 항목) |
| 투플 | 행 하나 (실제 값의 모음) |
| 도메인 | 속성 하나가 가질 수 있는 **모든 값의 집합** (예: 나이 = 0 이상 정수) |
| 차수 | 속성의 **개수** |
| 카디널리티 | 투플의 **개수** |
| 릴레이션 스키마 | `고객(고객아이디, 고객이름, 나이, 등급)` — 틀 |
| 릴레이션 인스턴스 | 어느 시점에 들어 있는 투플들의 집합 — 값 |

- 차수는 잘 안 바뀜, 카디널리티는 투플 삽입·삭제로 자주 바뀜
- 예: 차수 4, 투플 5개인 릴레이션에 3개 삽입, 1개 삭제 → 차수 **4**, 카디널리티 5 + 3 − 1 = **7**

## 2. 릴레이션의 특성 4가지

| 특성 | 뜻 |
|---|---|
| 투플의 유일성 | 한 릴레이션에 **동일한 투플이 존재할 수 없다** |
| 투플의 무순서 | 투플 순서는 의미 없음 |
| 속성의 무순서 | 속성 순서는 의미 없음 |
| 속성의 원자성 | 속성 값은 더 쪼갤 수 없는 **원자 값**만 |

## 3. 키의 종류

- **유일성**: 키 값으로 투플을 **하나씩 구별**할 수 있다
- **최소성**: 꼭 필요한 속성만으로 구성 (하나라도 빼면 유일성이 깨짐)

`학생(학번, 주민번호, 이름, 이메일, 학과코드)` 예시

| 키 | 조건 | 예 |
|---|---|---|
| 슈퍼키 | 유일성 ○, 최소성 × | `{학번}`, `{학번, 이름}`, `{주민번호, 학과코드}` |
| 후보키 | 유일성 ○, 최소성 ○ | `{학번}`, `{주민번호}`, `{이메일}` |
| 기본키 | 후보키 중 **하나를 선택** | `학번` |
| 대체키 | 기본키가 되지 못한 나머지 후보키 | `주민번호`, `이메일` |
| 외래키 | **다른 릴레이션의 기본키를 참조**하는 속성 | `학과코드` → 학과(학과코드) |

```
슈퍼키 ⊃ 후보키 ⊃ 기본키
```

**외래키 규칙**
- 참조되는 기본키와 **도메인이 같아야** 함 (속성 **이름은 달라도** 됨: `주문고객` → `고객아이디`)
- **NULL 가능**, **중복 가능** (기본키가 아니므로)
- 같은 릴레이션의 기본키를 참조할 수도 있음 (자기 참조: `멘토사원번호` → `사원번호`)

## 4. 무결성 제약조건

| 제약조건 | 교재 정의 문장 |
|---|---|
| 개체 무결성 | **기본키를 구성하는 모든 속성은 널 값을 가질 수 없다** |
| 참조 무결성 | **외래키는 참조할 수 없는 값을 가질 수 없다** |

참조 방향: **외래키 쪽(참조하는, 자식) → 기본키 쪽(참조되는, 부모)**
```
 학생(학번, 이름, 학과번호)  ──참조──▶  학과(학과번호, 학과명)
          외래키 (자식)                      기본키 (부모)
```

**참조 무결성 때문에 거부될 수 있는 연산**

| 릴레이션 | 위험한 연산 | 예 |
|---|---|---|
| 참조하는 쪽 (학생) | **삽입**, 외래키 **수정** | 없는 학과 `D9`로 학생 삽입 |
| 참조되는 쪽 (학과) | **삭제**, 기본키 **수정** | 학생이 다니는 학과 삭제 |

- 학생의 학과번호를 **NULL**로 삽입 → 참조 무결성 **위반 아님** (아직 학과 미정)
- 학과에 새 학과 삽입 → 문제 없음 (아무도 참조하지 않음)
