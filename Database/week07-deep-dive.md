## 1. SELECT 뒤에는 "열", 표 이름은 FROM 뒤에

### 처음 생각 (오답)
- "고객 테이블 전체를 검색하라"에 `SELECT 고객;`처럼 **SELECT 뒤에 테이블 이름**만 쓰고 `FROM`을 빠뜨렸다.
- 모든 열을 뜻하는 `*`를 몰랐다.
- `FROM`을 `form`으로 반복해서 잘못 썼다.

### 원리
```
SELECT  무엇을(열)      ← 열 이름, 모든 열이면 *
FROM    어디서(표)      ← 표 이름
WHERE   어떤 행만(조건)
```
```sql
SELECT * FROM 고객;                 -- 모든 열
SELECT 고객이름, 등급 FROM 고객;     -- 두 열만
```
`form`은 SQL 키워드가 아니라서 문법 에러가 난다.

### 깨달음
SQL 문장은 **"SELECT 열 FROM 표"**가 뼈대. 표 이름이 SELECT 바로 뒤에 오는 일은 없다.

## 2. 행과 열: SELECT는 열을, WHERE는 행을 고른다

### 처음 생각 (오답)
문제를 풀다가 행과 열을 다시 헷갈렸다. (5장에서 속성=열, 투플=행으로 정리했던 것)

### 원리
```
              SELECT 고객이름, 등급   ← 열(세로)을 고름
                     │        │
            고객아이디 고객이름  나이  등급
 WHERE ──▶  cat      김민준   23   gold    ← 행(가로)을 고름
 등급='gold' dog     이서연   31   vip
            owl      김하은   27   gold    ←
```
관계 대수와 짝지으면: **SELECT 열 = π**, **WHERE 조건 = σ**. (SQL의 SELECT와 관계 대수의 셀렉트 σ는 이름만 같고 하는 일이 다르다)

### 깨달음
"무엇을 **보여 줄까**?" → SELECT(열), "어떤 **것만**?" → WHERE(행).

## 3. "함께 출력"이면 원래 열도 SELECT에 쓴다 + AS

### 처음 생각 (오답)
"제품명과 단가를 검색하되 단가에 500을 더한 값도 **함께** 출력"에서 `단가 + 500`만 쓰고 원래 `단가` 열을 빠뜨렸다. 새 이름을 붙이는 `AS`도 몰랐다.

### 원리
```sql
SELECT 제품명, 단가, 단가 + 500 AS "조정단가" FROM 제품;
--     ①      ②    ③──────────────────────
```
```
제품명   | 단가 | 조정단가
초코쿠키 | 1500 | 2000
```
SELECT에 쓴 것만 결과에 나온다. 원래 값도 보고 싶으면 그 열을 따로 써야 한다.
`AS 별명`은 결과 화면의 열 이름만 바꾸고 표는 바꾸지 않는다.

### 깨달음
문제에 나온 출력 항목을 **하나씩 세어서** SELECT 뒤 개수와 맞춘다.

## 4. WHERE: `=` 하나, 값은 작은따옴표, 표 이름은 붙이지 않음

### 처음 생각 (오답)
아래는 그때 섞여 나온 실수들을 한 줄로 모은 것이다.
```sql
SELECT 제품명 FROM 제품 WHERE 제조업체 == "달빛제과"(제품);
```
- 같다를 `==`로 썼다 (C++·자바 습관)
- 문자 값을 **큰따옴표**로 썼다
- 조건 뒤에 `(제품)`처럼 **표 이름을 괄호로** 붙였다 (관계 대수 `σ[조건](릴레이션)` 습관)

### 원리
```
관계 대수    σ[제조업체 = '달빛제과'](제품)
                                   └ 릴레이션을 괄호로
SQL         SELECT … FROM 제품 WHERE 제조업체 = '달빛제과';
                          └ 표는 FROM에 이미 있음
```

| | 자바·C++ | SQL |
|---|---|---|
| 같다 | `==` | `=` |
| 다르다 | `!=` | `<>` |
| 문자 값 | `"…"` | `'…'` |
| 큰따옴표 | 문자열 | **이름**(별명) |

```sql
SELECT 제품명, 재고량, 단가 FROM 제품 WHERE 제조업체 = '달빛제과';
-- 초코쿠키 300 1500 / 버터과자 150 2500
```
> 참고: MySQL(기본 설정)과 sqlite는 `"달빛제과"`처럼 큰따옴표로 쓴 값도 문자열로 받아 줘서 결과가 나오긴 한다(sqlite로 확인). 하지만 표준 SQL과 교재 규칙은 **값 = 작은따옴표**, **이름 = 큰따옴표**다. 시험 답안은 이 규칙대로 쓴다.

### 깨달음
SQL은 **`=` 하나, 값은 `'작은따옴표'`**. 표 이름은 `FROM`에만 쓴다.

## 5. 열 이름과 값은 표에 있는 그대로

### 처음 생각 (오답)
- 주문 표의 열 이름 `주문고객`을 `고객`으로 썼다 (주문 표에는 `고객`이라는 열이 없다)
- 문제 조건의 값 `vip`를 `gold`로 잘못 옮겼다

### 원리
```
주문 표의 실제 열:  주문번호 | 주문고객 | 주문제품 | 수량 | 주문일자
                           ▲
     WHERE 고객 = 'cat'  ──┘ ✗ 그런 열 없음 → 에러
     WHERE 주문고객 = 'cat'   ✓
```
외래키는 참조하는 기본키와 **이름이 달라도** 된다(5장). 그래서 주문 표에서는 `고객아이디`도 `고객`도 아닌 `주문고객`이다.

### 깨달음
쓰기 전에 `SELECT * FROM 표;`로 **실제 열 이름**을 확인하고, 문제의 값은 한 글자씩 대조한다.

## 6. GROUP BY 뒤에는 "묶을 기준 열"

### 처음 생각 (오답)
"고객별 총주문수량"을 구할 때 `GROUP BY` 뒤에 **합계를 낼 열**(`주문.수량`)을 써서 원하는 결과가 나오지 않았다.

### 원리
```
"고객별   총주문수량"
  └기준┘   └ 집계 대상 ┘
GROUP BY 고객이름     SUM(수량)

수량으로 묶으면:  5끼리, 8끼리, 10끼리 … → 수량 값마다 한 그룹, SUM(수량)도 자기 자신
                 (5,5) (8,8) (10,10) (12,12) (15,15) (20,20)   ← sqlite 실행 결과
고객으로 묶으면:  김민준 [10, 5, 12] → 27
                 이서연 [20, 8]     → 28
                 김하은 [15]        → 15
```
```sql
SELECT   고객.고객이름, SUM(주문.수량) AS "총주문수량"
FROM     고객, 주문
WHERE    고객.고객아이디 = 주문.주문고객
GROUP BY 고객.고객이름
ORDER BY "총주문수량" DESC;
-- 이서연 28 / 김민준 27 / 김하은 15
```

### 깨달음
"**~별**"의 ~가 GROUP BY 뒤로, "**총·평균·개수**"가 집계 함수 안으로 간다. SELECT에는 기준 열과 집계 함수만.

## 7. 수업 메모의 `SUM(수량), AS` — AS 앞에는 쉼표가 없다

### 처음 생각 (오답)
수업 메모에 이렇게 적었다.
```sql
SELECT 주문제품, SUM(수량), AS "총주문수량" FROM 주문 GROUP BY 주문제품;
```

### 원리
쉼표는 **열과 열 사이**를 나눈다. `SUM(수량), AS …`라고 쓰면 `AS "총주문수량"`이 별개의 열처럼 읽혀 문법 에러가 난다.
```
SELECT  주문제품 ,  SUM(수량) AS "총주문수량"
        └ 열 1 ┘ ↑  └──── 열 2 (+별명) ─────┘
              열 구분
```
```sql
SELECT 주문제품, SUM(수량) AS "총주문수량" FROM 주문 GROUP BY 주문제품;
-- p1 10 / p2 47 / p3 5 / p4 8
```

### 깨달음
`AS`는 바로 앞 열에 **붙는** 꼬리표다. 쉼표는 다음 열로 넘어갈 때만.

# 프로그래밍기능사 실기 대비 중 틀린 것 (2026-11-12)

> 실기는 SQL을 **직접 써서** 답한다 (공단 예시문제 10번). 그래서 개념보다 철자·기호에서 점수가 샌다

## 8. CREATE TABLE: 내용은 맞는데 철자·기호가 틀림 (2회)

### 처음 생각 (오답)
```sql
CREAT TABLE 수강{
학번 CHAR(5) NOT NULL,
과목코드 CHAR(4),
성적 INT CHECK (성적 >= 0),
FOREIGN KEY 과목코드 REFERNCES 과목코드 (과목)
};
```
열·타입·제약조건 선택은 전부 맞았다. 첫 시도에서는 열 사이 쉼표와 `VARCHAR` 철자(`VERCHAR`)도 틀렸다.

### 원리
| 내 답 | 정답 | 이유 |
|---|---|---|
| `CREAT` | `CREATE` | 영어 단어 create 그대로 |
| `{ }` | `( )` | SQL에는 중괄호가 없다 (Java 습관) |
| `FOREIGN KEY 과목코드` | `FOREIGN KEY (과목코드)` | 외래키 열도 괄호 |
| `REFERNCES` | `REFERENCES` | refer + **ences** |
| `과목코드 (과목)` | `과목(과목코드)` | **테이블(열)**, 주소처럼 큰 것 → 작은 것 |

### 깨달음
고정 틀을 통째로 외웠더니 세 번째에 완벽하게 썼다.
```sql
CREATE TABLE 테이블명 (
    열이름  타입  제약조건,
    FOREIGN KEY (열이름) REFERENCES 다른테이블(열이름)
);
```

## 9. 별명과 숫자에 작은따옴표 (3회 반복)

### 처음 생각 (오답)
```sql
SELECT COUNT(이름) AS '학생 수' ...
HAVING 학년 >= "2"
```

### 원리
| 쓰임 | 표기 |
|---|---|
| 문자 **값** | 작은따옴표 `'컴공'` |
| 숫자 값 | 따옴표 없이 `2` |
| 별명(이름) | 따옴표 없이 `AS 학생수`, 공백이 필요하면 큰따옴표 `"학생 수"` |

### 깨달음
작은따옴표는 **값 전용**. 별명은 공백 없이 쓰면 따옴표 고민이 없다.

## 10. GROUP BY · HAVING 전체 작성 (3회) — 6번 "GROUP BY 기준 열"이 다시 나옴

### 처음 생각 (오답)
```sql
-- 학과별 학생 수와 평균, 2명 이상인 학과만
SELECT COUNT(이름) AS '학생 수', 점수 AS '평균 점수'
FROM 학생
WHERE 학과 IN (COUNT(학과) >= 2)

-- 학년별 최고 점수, 80 이상인 학년만
SELECT 학년, 점수 AS '최고 점수' FROM 학생 WHERE 학년
GRUOP BY 점수 HAVING 점수(점수 >= 80) ORDER BY 학년 ASC

-- 2학년 이상만 대상으로 학과별 점수 합계
SELECT SUM(점수) AS '점수 합계' FROM 학생 WHERE 학과
GROUP BY 학과 HAVING 학년 >= "2"
```
1회차는 GROUP BY 자체가 없었고, 2회차는 묶는 기준을 계산 대상(점수)으로 잡고 "최고"를 MAX로 바꾸지 못했고, 3회차는 개인 조건(2학년 이상)을 HAVING에 넣었다. `WHERE 학과`처럼 조건 없는 WHERE도 계속 붙였다.

### 원리
GROUP BY를 하면 한 묶음에 값이 여러 개다. 2학년 묶음의 점수는 85와 70 → "점수"라고만 쓰면 어느 걸 보여줄지 못 정한다. 그래서 SELECT·HAVING에는 **기준 열 또는 집계 함수**만 온다.

| 질문 | 학년별 최고 점수 (80 이상만) | 2학년 이상, 학과별 합계 |
|---|---|---|
| ① 무엇별 | `GROUP BY 학년` | `GROUP BY 학과` |
| ② 계산 | "최고" → `MAX(점수)` | "합계" → `SUM(점수)` |
| ③ 묶음 조건 | `HAVING MAX(점수) >= 80` | 없음 |
| ④ 개인 조건 | 없음 → WHERE 안 씀 | `WHERE 학년 >= 2` |

### 깨달음
조건의 **주어가 한 사람이면 WHERE, 묶음이면 HAVING**. 쓸 조건이 없으면 WHERE 자체를 쓰지 않는다. WHERE/HAVING 구분만 따로 4문항 물었을 때는 전부 맞혔다.

## 11. NULL과 `<>` 비교, DESC 정렬

### 처음 생각 (오답)
```sql
SELECT 이름 FROM 학생 WHERE 이름 LIKE '_지%' OR 점수 <> 85 ORDER BY 이름 DESC;
```
내 답: 최유리, 박지성, **박민**, **이영희** (정답: 최유리, 이영희, 박지성)

### 원리
- 박민의 점수는 NULL → `NULL <> 85`는 참이 아니라 **알 수 없음** → 탈락
- DESC는 남은 행을 **오름차순으로 세운 뒤 뒤집기**: 박(ㅂ) → 이(ㅇ) → 최(ㅊ)를 뒤집어 최 → 이 → 박

### 깨달음
NULL이 낀 비교는 `IS NULL`·`IS NOT NULL` 말고는 전부 탈락. 정렬은 머릿속 순서가 아니라 직접 세워서 확인한다.

## 12. 뷰: AS 뒤에 조건만 씀

### 처음 생각 (오답)
```sql
CREATE VIEW 우수학생 AS 점수>=90;
```

### 원리
뷰 = SELECT문에 이름을 붙인 것. AS 뒤에는 **SELECT문이 통째로** 온다.
```sql
CREATE VIEW 우수학생 AS
SELECT 이름, 점수 FROM 학생 WHERE 점수 >= 90;
```

## 정리

| 착각 | 바로잡은 규칙 |
|---|---|
| `SELECT 고객;` | **SELECT 열 FROM 표**, 전체 열은 `*` |
| `form` | `FROM` |
| 행/열 혼동 | SELECT = **열**, WHERE = **행** |
| "함께 출력"인데 새 값만 | 원래 열 + 계산 열 **둘 다**, 이름은 `AS` |
| `==`, `"값"` | `=`, `'값'` |
| 조건 뒤 `(표이름)` | 표는 **FROM**에만 (관계 대수 습관 버리기) |
| 주문 표에서 `고객` | 실제 열 이름 `주문고객` 확인 |
| `GROUP BY 수량` | GROUP BY = **"~별"의 기준 열** |
| `SUM(수량), AS …` | `SUM(수량) AS …` (쉼표 없음) |
| `CREAT`, `{ }`, `REFERNCES`, `열(테이블)` | `CREATE`, `( )`, `REFERENCES`, **`테이블(열)`** |
| `AS '별명'`, `"2"` | 별명은 따옴표 없이, 숫자도 따옴표 없이 (작은따옴표는 값 전용) |
| GROUP BY 기준을 계산 대상으로, "최고"를 그냥 열로 | "~별" = 기준 열, 최고 = `MAX` |
| 개인 조건을 HAVING에, 조건 없는 `WHERE 학과` | 한 사람 조건 = WHERE, 묶음 조건 = HAVING, 없으면 WHERE 생략 |
| `NULL <> 85`는 참 | NULL 비교는 **알 수 없음 → 탈락** |
| `CREATE VIEW 이름 AS 조건` | `AS` 뒤에 **SELECT문 전체** |
