## 1. 트랜잭션

- 작업 하나를 수행하는 데 필요한 DB 연산들을 모은 것 = **논리적인 작업 단위**
- 예: 계좌 이체 = `UPDATE` 2개 (보내는 쪽 −, 받는 쪽 +). 둘 다 성공하거나 둘 다 취소돼야 함

**ACID 특성**

| 특성 | 뜻 | 담당 기능 |
|---|---|---|
| 원자성 (Atomicity) | 연산이 **모두 실행되거나 하나도 실행되지 않음** | 회복 |
| 일관성 (Consistency) | 수행 후에도 DB가 **일관된 상태** 유지 | 병행 제어 |
| 격리성 (Isolation) | 수행 중인 트랜잭션의 **중간 결과**에 다른 트랜잭션이 접근 못 함 | 병행 제어 |
| 지속성 (Durability) | 성공적으로 완료된 결과는 **영구적**으로 반영 | 회복 |

**연산**: `COMMIT` = 성공 선언(작업 완료), `ROLLBACK` = 실패 선언(작업 취소, 원래대로)

```python
# 계좌 이체 (sqlite3로 실행해 확인)
try:
    cur.execute("UPDATE 계좌 SET 잔액 = 잔액 - ? WHERE 계좌번호 = ?", (금액, 보내는))
    cur.execute("UPDATE 계좌 SET 잔액 = 잔액 + ? WHERE 계좌번호 = ?", (금액, 받는))
    conn.commit()        # 둘 다 성공 → 반영
except sqlite3.Error:
    conn.rollback()      # 하나라도 실패 → 둘 다 취소
```
```
시작: A01 10000, B02 5000   (잔액 CHECK (잔액 >= 0))
3000원 이체 → COMMIT   → A01 7000, B02 8000
9000원 이체 → 첫 UPDATE가 CHECK 위반 → ROLLBACK → A01 7000, B02 8000 그대로
```

**상태 5가지**
```
           마지막 연산 실행 끝          commit 실행
 [활동] ───────────────▶ [부분 완료] ───────────▶ [완료]
   │                          │
   │ 장애·오류                 │ 장애·오류
   ▼                          ▼
 [실패] ─────────── rollback 실행 ───────────▶ [철회]
```

## 2. 장애와 회복

| 장애 | 원인 | 잃는 것 |
|---|---|---|
| 트랜잭션 장애 | 논리 오류, 잘못된 입력, 자원 부족 | 트랜잭션 하나 |
| 시스템 장애 | 하드웨어 결함, 정전, OS 오류 | **메인 메모리** 내용 |
| 미디어 장애 | 디스크 헤드 손상, 디스크 고장 | **디스크** 내용 |

**회복 준비물**: **덤프**(DB 전체를 주기적으로 다른 저장 장치에 복사) + **로그**(변경할 때마다 변경 **전** 값과 **후** 값을 기록)

| 연산 | 하는 일 | 쓰는 값 |
|---|---|---|
| redo (재실행) | 이미 commit된 작업을 **다시 실행**해 장애 직전 상태로 | 로그의 변경 **후** 값 |
| undo (취소) | 끝나지 못한 작업의 변경을 **취소**해 원래 상태로 | 로그의 변경 **전** 값 |

## 3. 회복 기법

| 기법 | 방식 | 장애 시 |
|---|---|---|
| 즉시 갱신 (로그 회복) | 실행 중에 바뀐 값을 DB에 **바로** 반영 (로그도 기록) | commit 된 것 **redo**, commit 안 된 것 **undo** |
| 지연 갱신 (로그 회복) | 실행 중에는 **로그에만** 기록, 부분 완료 후 DB에 한 번에 반영 | commit 된 것 **redo**만 (DB에 반영된 게 없으니 undo 불필요) |
| 검사 시점 (체크포인트) | 일정 간격으로 검사 시점을 기록 | 검사 시점 **이전**에 commit → 무시 / **이후** commit → redo / 장애 때까지 commit 못 함 → undo |
| 미디어 회복 | 주기적 덤프 | 최근 덤프로 복원 → 덤프 이후 로그로 commit 된 작업 redo |

```
            검사 시점                장애
 ───────────────┼──────────────────────┼────▶ 시간
 T1 ━━━━commit  │                      │      → 아무것도 안 함
 T2       ━━━━━━┼━━━commit             │      → redo
 T3             │       ━━━━━━━━━━━━━━━┥      → undo (commit 못 함)
```

## 4. 병행 제어

- **병행 수행**: 여러 트랜잭션을 번갈아 가며 동시에 실행
- **병행 제어**: 그렇게 섞어 실행해도 **하나씩 차례로 실행한 것과 같은 결과**가 나오게 조절

**병행 수행의 문제 3가지**

| 문제 | 뜻 |
|---|---|
| 갱신 분실 | 한 트랜잭션이 바꾼 값을 다른 트랜잭션이 **덮어써서** 사라짐 |
| 모순성 | 여러 값을 읽는 도중 다른 트랜잭션이 값을 바꿔 **앞뒤가 안 맞는** 값을 읽음 |
| 연쇄 복귀 | T1이 바꾼 값을 T2가 읽고 썼는데 T1이 rollback → T2도 rollback해야 함 (T2가 이미 commit했으면 불가) |

```
갱신 분실 예 (재고 10)
 T1: read 재고=10              T1: write 재고=10-3=7
 T2:        read 재고=10                          T2: write 재고=10-2=8
 결과 8 (정답 5) → T1의 변경이 사라짐
```

**트랜잭션 스케줄**

| 스케줄 | 방식 | 결과 |
|---|---|---|
| 직렬 | 하나 끝나고 다음 | 항상 정확, 느림 |
| 비직렬 | 연산을 섞어 실행 | 문제 생길 수 있음 |
| 직렬 가능 | 섞었지만 결과가 직렬과 같음 | 정확, 빠름 ← 병행 제어의 목표 |

## 5. 로킹

- 데이터를 쓰기 전에 **lock**, 다 쓰면 **unlock**. lock 걸린 데이터는 다른 트랜잭션이 함부로 못 씀

| lock | lock을 건 트랜잭션 | 다른 트랜잭션 |
|---|---|---|
| 공용 lock (읽기용) | read 가능, write 불가 | **공용 lock은 같이 걸 수 있음** (같이 읽기 OK) |
| 전용 lock (쓰기용) | read, write 가능 | 어떤 lock도 못 걺 |

- 로킹만으로는 lock을 너무 빨리 풀면 직렬 가능성을 보장 못 함 → **2단계 로킹 규약(2PL)**
  - 확장 단계: lock만 걸 수 있음 / 축소 단계: unlock만 할 수 있음
  - 모든 트랜잭션이 2PL을 지키면 **직렬 가능성 보장**, 대신 **교착 상태**가 생길 수 있음

**교착 상태 (deadlock)**: 서로 상대가 가진 lock을 기다리며 아무도 진행 못 함
```
T1: lock(A) ──── 기다림: B ───┐
                              ▼
T2: lock(B) ──── 기다림: A ◀──┘    (환형 대기)
```
- 발생 조건 4가지: 상호 배제, 점유와 대기, 비선점, 환형 대기
- 해결: **예방**(조건 하나를 원천 차단, 예: 필요한 lock을 시작할 때 모두 걸기) / **회피**(타임스탬프로 우선순위를 정해 기다리게 하거나 철회) / **탐지 후 회복**(발견하면 희생자 하나를 골라 rollback)

```
병행 수행 문제 → 로킹으로 막음 → 로킹만으론 부족 → 2PL로 직렬 가능성 보장 → 교착 상태 가능 → 탐지해서 rollback
```

## 6. 파이썬에서 MySQL 쓰기 (pymysql)

```
pip install pymysql
```
수업에서 한 두 가지 흐름을 직접 만든 예로 정리 (같은 흐름을 sqlite3로 바꿔 실행해 확인, 차이는 `connect` 줄과 자리표시자 `%s` ↔ `?`뿐)

```python
import pymysql

conn = pymysql.connect(host='127.0.0.1', user='root', password='비밀번호',
                       db='shop', charset='utf8')
cur = conn.cursor()                 # 커서: SQL을 보내고 결과를 한 행씩 꺼내는 도구

# ① 입력받아 INSERT (빈 아이디를 입력하면 종료)
while True:
    아이디 = input("고객아이디 ==> ")
    if 아이디 == "":
        break
    이름 = input("고객이름 ==> ")
    나이 = input("나이 ==> ")
    cur.execute("INSERT INTO 고객 VALUES (%s, %s, %s)", (아이디, 이름, int(나이)))
conn.commit()                       # commit 해야 DB에 반영

# ② SELECT 결과를 커서로 한 행씩
cur.execute("SELECT * FROM 고객")
while True:
    row = cur.fetchone()            # 한 행 (튜플), 더 없으면 None
    if row is None:
        break
    print(row[0], row[1], row[2])

conn.close()
```
```
(입력: cat/김민준/23, dog/이서연/31, 빈 줄)
cat 김민준 23
dog 이서연 31
```
- 수업 예제는 SQL 문자열을 `+`로 이어 붙였는데, 값은 `execute(sql, (값들))`처럼 **따로 넘기는 것**이 안전하다 (작은따옴표 처리 실수, SQL 삽입 공격 방지)
- 7장 "삽입 SQL·커서"가 바로 이것: 프로그램 안에 SQL을 넣고, 여러 행 결과는 커서로 하나씩 꺼낸다
