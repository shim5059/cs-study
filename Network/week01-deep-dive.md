## 1. 라우팅에서 IP와 MAC의 역할 순서

### 처음 생각 (오답)
목적지 MAC 주소는 라우터를 거칠 때마다 갈아 끼워지고 목적지 IP 주소는 동일하다는 건 알았는데, **"MAC 주소를 따라가다 보면 마지막 라우터에서 최종 IP 주소가 공개되는 것"**이라고 반대로 생각했다. 또한 짜장면 배달 비유에서 차량 고유 번호판(`42222`)을 목적지 IP라고 답했다.

### 원리
출발하기 **전에** 이미 DNS를 통해 최종 목적지의 **IP 주소**를 알아내어 패킷에 적어 둔다. 각 라우터는 그 **목적지 IP를 읽고** 다음 경로를 정한 뒤, 그 구간을 건너기 위한 **다음 장비의 MAC 주소**를 프레임에 새로 붙인다.

```text
내 PC ──────→ 라우터 A ──────→ 라우터 B ──────→ 웹 서버
목적지 IP :  서버 IP          서버 IP          서버 IP      (처음부터 알고 있음, 끝까지 유지)
목적지 MAC:  라우터 A의 MAC   라우터 B의 MAC   서버의 MAC   (IP를 보고 구간마다 ARP로 찾아 교체)
```

짜장면 배달 비유와 매칭하면 다음과 같다.

```text
극장 2열 3번 자리  →  어디에 있는지 나타내는 위치(논리 주소)  →  IP 주소
차량 번호판 42222  →  차 자체에 붙은 고유 번호(물리 주소)    →  MAC 주소
차 안의 1번 사람   →  어느 프로그램에게 줄지                 →  포트 번호
```

### 깨달음
**IP가 길을 정하고, MAC은 그 길의 한 구간만 배달**한다. 마지막 구간에서 ARP로 새로 알아내는 것은 IP가 아니라 **목적지의 MAC 주소**다.

## 2. 헤더와 페이로드의 역할 뒤바뀜

### 처음 생각 (오답)
1장 연습문제에서 패킷의 구성 요소를 쓸 때 `헤더 = 실제 데이터`, `페이로드 = 데이터를 꺼내기 위한 정보(역캡슐화에 사용)`라고 정반대로 적었다.

### 원리

```text
┌──────────────────────┬──────────────────────────────┐
│      헤더(Header)     │        페이로드(Payload)       │
│  출발지·목적지·순서 등  │         실제 전송 데이터        │
│    (택배 상자 송장)    │         (상자 안의 물건)        │
└──────────────────────┴──────────────────────────────┘
```

- 캡슐화할 때 계층마다 앞에 덧붙이고, 역캡슐화할 때 하나씩 읽고 **떼어내는 겉부분이 헤더**다.
- 헤더를 다 떼어내고 마지막에 남는 **속 알맹이가 페이로드**다.

### 깨달음
**헤더 = 겉(송장·제어 정보), 페이로드 = 속(실제 데이터)**. 답을 쓴 뒤 겉과 속이 바뀌지 않았는지 한 번 더 확인한다.

## 3. OSI 2계층(데이터링크·프레임)과 3계층(네트워크·패킷) 순서 혼동

### 처음 생각 (오답)
OSI 7계층을 아래부터 적을 때 `물리 → 네트워크 → 데이터링크 → 전송` 순으로 2·3계층을 뒤집어 적었고, PDU를 묻는 문제에서도 `프레임 = 네트워크 계층`, `패킷 = 데이터링크 계층`으로 반대로 답했다.

### 원리
계층은 아래에서 위로 갈수록 통신 범위가 넓어진다.

```text
4계층 전송       : 세그먼트 + 포트  → 컴퓨터 안의 프로그램까지
3계층 네트워크    : 패킷     + IP    → 다른 동네(네트워크)까지  [라우터]
2계층 데이터링크  : 프레임   + MAC   → 같은 동네(LAN) 안 한 구간 [스위치]
1계층 물리       : 비트             → 전선·전파 신호 (0과 1)
```

### 깨달음
아래에서 위로 **"동네 안(2계층 데이터링크) → 동네 밖(3계층 네트워크)"** 순서다. 그리고 주소와 단위는 항상 세트로 묶는다: **세그먼트-포트(4), 패킷-IP(3), 프레임-MAC(2)**.

## 4. 스위치가 MAC 주소를 쓰는 이유와 PAN의 범위

### 처음 생각 (오답)
- 스위치는 연결된 장비 수가 적어서 MAC 주소를 쓰고, 라우터는 장비 수가 많아서 IP를 쓴다고 생각했다.
- 한 PC 안에서 크롬과 카카오톡을 포트로 구분하는 상황을 `PAN(Personal Area Network)`이라고 생각했다.

### 원리
- **MAC vs IP의 구조 차이**: MAC 주소는 제조사가 부여한 일련번호(주민번호처럼)라 **어느 네트워크에 있는지 위치 정보가 없다.** 그래서 같은 LAN 안에서만 쓸 수 있다. 반면 IP 주소는 **네트워크 부분 + 호스트 부분**으로 나뉜 계층 구조(도로명 주소처럼)라 라우터가 네트워크 단위로 묶어서 경로를 찾을 수 있다.
- **PAN vs 호스트 내부**: PAN·LAN·WAN은 **서로 다른 기기들 사이의 거리**로 나누는 분류다(예: 스마트폰 ↔ 블루투스 이어폰 = PAN). 컴퓨터 **한 대 안에서** 프로그램을 구분하는 것은 네트워크가 아니라 OS가 포트 번호로 처리하는 일이다.

### 깨달음
스위치와 라우터의 차이는 장비 개수가 아니라 **주소의 구조(평면 번호 vs 계층 주소)** 때문이고, 한 PC 안의 프로세스 구분은 네트워크 범위 분류(PAN~WAN)에 해당하지 않는다.

## 정리

| 착각 | 바로잡은 규칙 |
|---|---|
| MAC을 따라가다 마지막에 IP가 공개됨 | 출발 전 DNS로 IP를 먼저 앎, 구간마다 바뀌는 건 MAC |
| 차량 번호판 = IP, 자리 번호 = MAC | 위치(자리) = 논리 주소(IP), 고유 번호판 = 물리 주소(MAC) |
| 헤더 = 실제 데이터, 페이로드 = 제어 정보 | 헤더 = 겉(송장·제어 정보), 페이로드 = 속(실제 데이터) |
| 2계층 패킷(네트워크) · 3계층 프레임(데이터링크) | 2계층 데이터링크(프레임·MAC) → 3계층 네트워크(패킷·IP) |
| 한 PC 안 프로그램 구분 = PAN | 한 PC 내부는 OS가 포트로 구분, PAN은 기기 간 근거리 망 |
