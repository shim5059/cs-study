# 1주차 · 네트워크 기초와 계층 모델

> 헷갈렸던 부분과 해결 과정: [week01-deep-dive.md](week01-deep-dive.md)

> 교재: 『컴퓨터 네트워크』 1장 (네트워크 구성요소 · 패킷 · 주소 3종 · OSI 7계층 · 캡슐화)

## 1. 네트워크의 구성요소

| 구성요소 | 의미 | 예시 |
|---|---|---|
| **노드(Node)** | 데이터를 송수신하거나 전달하는 장치 | PC, 스마트폰, 서버, 라우터, 스위치 |
| **링크(Link)** | 노드와 노드를 연결하는 물리적·무선 통신 경로 | UTP 케이블, 광섬유, Wi-Fi, 5G |
| **프로토콜(Protocol)** | 데이터를 주고받기 위한 통신 규칙 | IP, TCP, UDP, HTTP, DNS |

- **인터넷**: 여러 네트워크를 TCP/IP 표준 프로토콜로 묶은 **"네트워크의 네트워크"** (인프라)
- **웹(WWW)**: 인터넷 위에서 브라우저로 문서를 주고받는 **서비스 중 하나** (이메일, 게임도 인터넷을 쓰지만 웹은 아님)

## 2. 인터넷의 구조적 분류

```text
[종단 시스템] ──→ [액세스 네트워크] ──→ [코어 네트워크]
(PC, 스마트폰,     (공유기, Wi-Fi AP,     (통신사 백본망,
 서버)              통신사 기지국)          라우터 그물망)
```

- **종단 시스템(End System, 호스트)**: 네트워크 가장자리에서 데이터를 만들고 소비하는 기기
- **액세스 네트워크**: 종단 시스템을 인터넷에 처음 접속시키는 진입로 구간
- **코어 네트워크**: 액세스 네트워크들을 서로 연결하는 인터넷의 중심 고속도로

## 3. 패킷(Packet)
- 큰 데이터를 잘게 나누어 보내는 네트워크 전송의 기본 단위
- **헤더(Header)**: 출발지·목적지 주소, 순서 번호 등 **제어 정보** (택배 송장)
- **페이로드(Payload)**: 실제로 전송하려는 **알맹이 데이터** (상자 속 물건)
- **MTU(Maximum Transmission Unit)**: 한 프레임에 실을 수 있는 최대 크기 (이더넷 기준 보통 **1500 Byte**)

## 4. 주소 3종 (MAC · IP · 포트)

| 주소 | 계층 | 구분 대상 | 범위 | 보는 장비 |
|---|---|---|---|---|
| **MAC 주소** | 2계층(데이터링크) | 랜카드(NIC)에 부여된 **물리 주소** | 같은 LAN 안 (한 구간) | 스위치 |
| **IP 주소** | 3계층(네트워크) | 네트워크상의 위치를 나타내는 **논리 주소** | 서로 다른 네트워크 사이 (끝에서 끝) | 라우터 |
| **포트 번호** | 4계층(전송) | 한 컴퓨터 안의 **프로세스(프로그램)** | 호스트 내부 | 운영체제(OS) |

- 자주 쓰는 포트: HTTP **80**, HTTPS **443**, DNS **53**, SMTP **25**
- 패킷이 라우터를 지날 때마다 **MAC 주소는 다음 구간 장비의 MAC으로 바뀌고, IP 주소와 포트 번호는 끝까지 유지**된다.

## 5. OSI 7계층과 TCP/IP 4계층

| OSI 7계층 | 하는 일 | PDU (데이터 단위) | 주소 · 장비 | TCP/IP 4계층 |
|---|---|---|---|---|
| **7 응용** | 사용자 서비스 제공 (HTTP, DNS, SMTP) | **데이터(메시지)** | — | **응용** |
| **6 표현** | 데이터 형식 변환, 암호화, 압축 | **데이터** | — | **응용** |
| **5 세션** | 통신 세션(대화) 시작·유지·종료 | **데이터** | — | **응용** |
| **4 전송** | 프로세스 간 전달, 신뢰성(TCP)·속도(UDP) | **세그먼트**(TCP) / **데이터그램**(UDP) | 포트 번호 | **전송** |
| **3 네트워크** | 다른 네트워크로 경로 결정(라우팅) | **패킷** | IP · 라우터 | **인터넷** |
| **2 데이터링크** | 같은 LAN 안 전달, 오류 검출 | **프레임** | MAC · 스위치 | **네트워크 액세스(링크)** |
| **1 물리** | 0과 1을 전기·빛·전파 신호로 전송 | **비트** | 케이블 · 허브 | **네트워크 액세스(링크)** |

- **계층화의 장점**: 각 계층이 독립적으로 발전할 수 있고(Wi-Fi를 유선으로 바꿔도 HTTP는 그대로), 서로 다른 제조사 장비 간 **상호운용성**이 높아지며, 장애 발생 시 몇 계층 문제인지 범위를 좁히기 쉽다.

## 6. 캡슐화와 역캡슐화

```text
응용       [데이터]
전송       [TCP 헤더(포트)][데이터]                      ← 세그먼트
네트워크   [IP 헤더(IP)][TCP 헤더][데이터]                ← 패킷
데이터링크 [MAC 헤더][IP 헤더][TCP 헤더][데이터][FCS]     ← 프레임
물리       0101 1100 ...                                 ← 비트
```

- **캡슐화(송신)**: 상위 계층에서 하위 계층으로 내려가며 각 계층의 **헤더를 차례로 붙이는** 과정 (2계층 끝에는 오류 검출용 **FCS**도 붙음)
- **역캡슐화(수신)**: 하위 계층에서 상위 계층으로 올라가며 **헤더를 하나씩 떼어내고** 원본 데이터를 복원하는 과정

## 7. 허브 · 스위치 · 라우터

| 장비 | 계층 | 동작 방식 |
|---|---|---|
| **허브(Hub)** | 1계층 | 들어온 신호를 **모든 포트로 무조건 뿌림** (플러딩) |
| **스위치(Switch)** | 2계층 | **MAC 주소 테이블**을 보고 목적지 포트로만 전달 (단, 테이블에 없는 주소는 플러딩 후 학습) |
| **라우터(Router)** | 3계층 | **IP 주소와 라우팅 테이블**을 보고 다른 네트워크로 가는 최적 경로를 결정 |
