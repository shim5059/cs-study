## 1. 회선 교환 / 패킷 교환 자리에 프로토콜 이름을 씀

### 처음 생각 (오답)
"경로를 독점하는 방식과 잘게 나눠 보내는 방식의 이름은?"이라는 질문에 1차 점검에서는 `TCP / UDP`라고 답했고, 2차 점검에서는 `HTTP/1.1 / HTTP/2`라고 답했다.

### 원리
질문이 묻는 것은 특정 계층의 프로토콜이 아니라 **네트워크 코어가 데이터를 전달하는 근본 방식** 두 가지다.

```text
회선 교환 (Circuit Switching) : 통신 전에 길을 통째로 예약하고 독점  → 옛날 전화망
패킷 교환 (Packet Switching)  : 패킷 단위로 쪼개 빈 길로 나눠 전송   → 인터넷 (TCP, UDP, HTTP 모두 이 위에서 동작)
```

여러 사람이 같은 도로와 라우터를 나눠 쓰는 **패킷 교환**이기 때문에, 차가 몰리면 줄을 서는 **큐잉 지연**과 버퍼가 넘쳐 버려지는 **패킷 손실**이 발생한다.

### 깨달음
"독점 vs 쪼개서 공유(큐잉 지연·손실 발생)"를 물으면 프로토콜(TCP/UDP/HTTP)이 아니라 **회선 교환 vs 패킷 교환**이다.

## 2. 지연 4종류와 지터(Jitter)의 혼동

### 처음 생각 (오답)
- 지연 4종류를 쓸 때 세 번 연속으로 `큐잉 지연`과 `전파 지연`만 쓰고, 나머지 두 개를 `패킷 지연`, `재해 지연`처럼 없는 이름으로 적었다.
- "지연 시간이 들쭉날쭉한 정도"를 묻는 문제에 `RTT` 또는 `큐잉 지연`이라고 답했다.

### 원리
패킷이 라우터 한 대를 통과할 때의 순서를 따라가면 4가지가 빠짐없이 나온다.

```text
① 처리 지연 : 라우터가 패킷 헤더를 읽고 경로를 결정하는 시간
② 큐잉 지연 : 출력 대기열(큐)에서 자기 차례를 기다리는 시간
③ 전송 지연 : 패킷의 비트들을 선로 위로 다 밀어내는 시간 (패킷 크기 / 대역폭)
④ 전파 지연 : 선로를 타고 다음 라우터까지 날아가는 시간 (거리 / 신호 속도)
```

그리고 그 지연 시간이 `20ms → 120ms → 30ms`처럼 **흔들리는 정도**는 **지터(Jitter)** 다.

### 깨달음
지연 4종은 라우터 통과 순서대로 **"처·큐·전·전"(처리 → 큐잉 → 전송 → 전파)** 으로 외우고, **"들쭉날쭉 / 흔들림"** 이라는 단어가 나오면 **지터**다.

## 3. 대역폭 vs 처리량 vs 지연 비유 섞임

### 처음 생각 (오답)
- "대역폭과 지연의 차이를 비유로 설명하시오"라는 문제에 "대역폭은 200인데 실제 속도는 10MB다"라고 **대역폭 vs 처리량** 예시를 적었다.
- 객관식에서 처리량(Throughput)의 정의로 `① 링크가 제공하는 이론적 최대 용량`을 골랐다.

### 원리

| 지표 | 핵심 키워드 | 도로 비유 |
|---|---|---|
| **대역폭** | **이론적 최대** 용량 | 도로의 **차선 수** (8차선) |
| **처리량** | **실제 측정된** 전송량 | 실제로 1초에 통과한 차량 수 |
| **지연** | 도착까지 **걸리는 시간** | 서울에서 부산까지 **이동 시간** |

8차선 도로(대역폭 큼)여도 거리가 멀면 도착 시간(지연)은 오래 걸린다.

### 깨달음
객관식과 서술형에서 **이론·최대 = 대역폭**, **실제·측정 = 처리량**, **시간·거리 = 지연**으로 키워드를 정확히 짝짓는다.

## 4. `ping` · `tracert` · `nslookup` · `ipconfig` 역할 섞임

### 처음 생각 (오답)
- `ping`의 목적을 "IP 주소의 확인"이라고 답했다.
- "도메인의 IP를 조회하는 명령어" 칸에 `ipconfig`를 적고, `nslookup`은 무엇을 하는지 몰랐다.

### 원리

```text
ipconfig  → "내 컴퓨터"의 IP·서브넷 마스크·기본 게이트웨이 확인
nslookup  → "상대 도메인(www.naver.com)"의 IP 주소를 DNS 서버에 물어봄 (ns = Name Server)
ping      → 그 IP까지 패킷이 "도달하는지 + 왕복 시간(RTT)" 확인
tracert   → 그 IP까지 가는 길에 "어느 라우터(홉)들을 거치는지" 경로 추적
```

### 깨달음
내 주소는 `ipconfig`, 남의 도메인 주소는 `nslookup`, 살아있는지 찔러보는 건 `ping`, 가는 길 추적은 `tracert`.

## 5. Wireshark 프레임 번호와 바이트 크기를 패킷 개수로 착각

### 처음 생각 (오답)
Wireshark 상세 창의 `Frame 350: Packet, 1206 bytes on wire (9648 bits)` 줄을 보고 "프레임은 300여 개인데 패킷은 1200개다"라고 읽었다.

### 원리
- `Frame 350`: 캡처 시작 후 **350번째**로 잡힌 프레임이라는 뜻이다.
- `1206 bytes`: 이 프레임 **한 개의 크기**가 1206바이트라는 뜻이다.
-その 1206바이트 상자 하나를 바깥에서 안쪽으로 열면 계층별 크기가 줄어든다.
  - 2계층 이더넷 프레임 전체: `1206 B` (이더넷 헤더 14 B 포함)
  - 3계층 IP 패킷: `1206 - 14 = 1192 B` (IP 헤더 20 B 포함)
  - 4계층 UDP 데이터그램: `1192 - 20 = 1172 B` (UDP 헤더 8 B 포함)
  - 응용(QUIC) 페이로드: `1172 - 8 = 1164 B`

### 깨달음
Wireshark 목록의 한 줄은 패킷(프레임) 1개이며, 그 한 개 안에 `[이더넷 헤더 [IP 헤더 [UDP 헤더 [데이터]]]]`가 포개져 들어 있다.

## 정리

| 착각 | 바로잡은 규칙 |
|---|---|
| 독점 vs 나눠 보내기 = TCP vs UDP | 회선 교환(독점) vs 패킷 교환(공유, 큐잉 지연·손실 발생) |
| 지연 4종 중 전송·처리 지연 누락 | 라우터 통과 순서: 처리 → 큐잉 → 전송 → 전파 |
| 지연의 흔들림 = RTT / 큐잉 지연 | 지연의 흔들림 = 지터(Jitter) |
| 처리량 = 이론적 최대 용량 | 이론 최대 = 대역폭, 실제 측정량 = 처리량 |
| `ping` = IP 주소 확인 | `ping` = 도달 여부·RTT 확인, 도메인 IP 조회는 `nslookup` |
