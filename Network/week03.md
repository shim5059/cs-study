## 1. 응용 계층과 소켓(Socket)

| 서비스 | 프로토콜 | 기본 포트 | 전송 계층 |
|---|---|---|---|
| 웹(평문 / 암호화) | HTTP / HTTPS | **80 / 443** | TCP (HTTP/3는 UDP 기반 QUIC) |
| 도메인 → IP 변환 | DNS | **53** | UDP (응답이 크면 TCP) |
| 메일 발송·전달 | SMTP | **25** (서버 간), **587** (제출) | TCP |
| 메일 조회 | IMAP / POP3 | **143(993) / 110(995)** | TCP |
| 파일 전송 | FTP | **20**(데이터) / **21**(제어) | TCP |

- **소켓(Socket)**: 응용 프로그램이 네트워크와 데이터를 주고받기 위해 여는 **통신 출입구(끝점)**
- **소켓 주소**: `IP주소:포트번호` (예: `223.130.200.236:443`)

## 2. 클라이언트-서버 vs P2P

| 구분 | 클라이언트-서버 | P2P (Peer-to-Peer) |
|---|---|---|
| **구조** | 항상 켜져 있는 **중앙 서버**에 클라이언트가 요청 | 모든 참가자(Peer)가 **동등하게** 요청과 응답을 주고받음 |
| **확장성** | 접속자가 늘면 **서버 부담 증가** | 참가자가 늘수록 **공급자도 함께 늘어** 잘 버팀 |
| **예시** | 웹, 이메일, 일반 게임 서버 | 토렌트(BitTorrent), 일부 화상통화 |

## 3. DNS (Domain Name System)
사람이 읽는 **도메인 이름**(`www.naver.com`)을 컴퓨터가 찾아가는 **IP 주소**로 변환하는 시스템이다.

### 1) DNS 캐시 확인 순서와 TTL
```text
① 브라우저 캐시 ──→ ② OS(윈도우) 캐시 ──→ ③ 공유기 캐시 ──→ ④ 통신사 재귀 리졸버
```
- **TTL (Time To Live)**: DNS 응답을 캐시에 보관해도 되는 **유효기간(단위: 초)**
- 윈도우 DNS 캐시 삭제 명령: `ipconfig /flushdns`

### 2) 계층적 질의 과정 (캐시에 없을 때)
```text
내 PC ──①──→ 재귀 리졸버(통신사 DNS, 8.8.8.8 등)
                  ├──②──→ 루트(.) DNS        ("com TLD 서버로 가봐")
                  ├──③──→ TLD(.com) DNS     ("naver 권한 DNS로 가봐" - NS 레코드)
                  └──④──→ 권한(Authoritative) DNS ("원본 정답은 223.130.200.236이야!")
내 PC ←──⑤── 최종 IP 전달 및 TTL 동안 캐시 저장
```

### 3) 주요 DNS 레코드

| 레코드 | 의미 | 비고 |
|---|---|---|
| **A** | 도메인 → **IPv4** 주소 (32비트) | Address |
| **AAAA** | 도메인 → **IPv6** 주소 (128비트) | IPv4보다 4배 길어서 A가 4개 |
| **CNAME** | 도메인의 **별칭(별명)** → 정식 도메인 이름 | Canonical Name |
| **MX** | 해당 도메인의 **메일을 수신할 서버** | `nslookup -type=mx 도메인`으로 조회 |
| **NS** | 해당 도메인의 **권한 DNS 서버** 지정 | Name Server |
| **TXT** | 자유 형식 텍스트 (도메인 소유 확인, **SPF·DKIM·DMARC** 등) | Text |

## 4. URL 구조

```text
https://shop.example.com:443/products/shoes?color=red&size=270#review
└─┬─┘   └──────┬───────┘ └┬┘└──────┬──────┘└────────┬────────┘└──┬──┘
 스킴        호스트       포트     경로             쿼리         프래그먼트
```
- **스킴(Scheme)**: 사용할 프로토콜 (`http`, `https`)
- **호스트(Host)**: 접속할 서버의 도메인 이름 또는 IP (**DNS** 단계에서 사용)
- **포트(Port)**: 서버 안의 프로세스 창구 번호 (기본값 `http=80`, `https=443`은 생략 가능)
- **경로(Path)**: 서버 안에서 요청할 자원의 위치
- **쿼리(Query)**: `?`로 시작하며 `키=값&키=값` 형태로 서버에 전달하는 추가 조건
- **프래그먼트(Fragment)**: `#`으로 시작하며 문서 내 특정 위치로 스크롤할 때 사용 (**서버로 전송되지 않고 브라우저에서만 처리**)

## 5. HTTP 메시지 구조와 메서드(GET vs POST)

```text
┌──────────────────────────────────────────────┐
│ 시작줄   GET /posts/12 HTTP/1.1   (요청)     │
│          HTTP/1.1 200 OK          (응답)     │
├──────────────────────────────────────────────┤
│ 헤더     Host: blog.example.com              │
│          Content-Type: text/html             │
├──────────────────────────────────────────────┤
│          (빈 줄 - 헤더와 본문의 경계)          │
├──────────────────────────────────────────────┤
│ 본문     실제 데이터 (HTML 문서, 폼 데이터 등) │
└──────────────────────────────────────────────┘
```
- **요청 시작줄**: `메서드 + 요청 경로 + HTTP 버전`
- **응답 시작줄**: `HTTP 버전 + 상태 코드 + 설명 문구`
- 브라우저는 HTML을 받은 뒤 그 안에 연결된 **이미지, CSS, JavaScript** 등의 추가 리소스를 연달아 요청한다.

| 구분 | GET | POST |
|---|---|---|
| **목적** | 서버의 리소스 **조회(가져오기)** | 서버에 데이터 **제출·생성·처리 요청** |
| **데이터 위치** | **URL의 쿼리**(`?key=value`)에 노출 | **HTTP 본문(Body)** 에 담아 전송 |
| **보안 주의** | URL에 그대로 보임 | 주소창에 안 보일 뿐 평문(HTTP)이면 스니핑 가능 → **HTTPS 필요** |

## 6. HTTP 상태 코드

| 분류 | 의미 | 주요 상태 코드 |
|---|---|---|
| **1xx** | 정보 (처리 중) | — |
| **2xx** | **성공** | **200 OK** (정상 처리), 201 Created (생성됨), 204 No Content |
| **3xx** | **리다이렉션** (다른 곳으로 이동) | **301** (영구 이동), **302** (임시 이동), **304 Not Modified** (변경 없음, 캐시 사용) |
| **4xx** | **클라이언트 오류** | **400** (잘못된 요청), **401** (인증 필요), **403** (권한 없음), **404** (찾을 수 없음), 429 (요청 과다) |
| **5xx** | **서버 오류** | **500** (서버 내부 코드 오류), **502** (Bad Gateway), **503** (과부하·점검), **504** (Gateway Timeout) |

## 7. 무상태성(Stateless)과 쿠키 · 세션
- **무상태성(Stateless)**: HTTP는 각 요청을 독립적으로 처리하며 **이전 요청의 상태를 기억하지 않는다.** (서버 부담 감소, 대신 그냥 두면 페이지 이동마다 로그인이 풀림)
- **쿠키(Cookie)**: 서버가 `Set-Cookie` 응답 헤더로 내려보내 **사용자의 브라우저에 저장**하는 작은 데이터 조각 (이후 요청마다 브라우저가 `Cookie` 헤더에 자동 첨부)
- **세션(Session)**: 민감한 사용자 상태 정보는 **서버 장부에 저장**하고, 브라우저에는 식별용 번호표(**세션 ID**)만 쿠키에 담아 전달하는 방식
