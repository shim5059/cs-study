## 1. UDP 헤더 4칸에 `데이터`와 `IP`, `Window Size`를 섞어 넣음

### 처음 생각 (오답)
- UDP 헤더 4필드를 적을 때 세 번 연속으로 `송신지 포트 / 수신지 포트 / 데이터 / 검사합` 또는 `헤더 / IP / 데이터`라고 적었다.
- 객관식 "UDP 헤더 필드를 모두 고르시오(`① Source Port ② Destination Port ③ Window Size ④ Checksum`)"에서 `④ Checksum` 하나만 골랐다.

### 원리
1. **데이터(페이로드)** 는 헤더 **바깥(아래)** 에 붙는 알맹이지 헤더의 칸이 아니다.
2. **IP 주소**는 한 층 아래인 **3계층 IP 헤더**에 들어간다. 4계층 전송 헤더에는 **포트 번호**만 들어간다.
3. **Window Size(`rwnd`)** 는 수신 버퍼 여유량을 알리는 **TCP 흐름 제어 전용 필드**이므로 UDP에는 없다.

```text
UDP 헤더 4칸 (8 Byte) = [ 송신지 포트 ] + [ 수신지 포트 ] + [ 전체 길이 ] + [ 검사합(체크섬) ]
                        (   포       ·       포       ·      길      ·       검   )
```

### 깨달음
UDP 헤더 4칸은 **"포·포·길·검"(송신지 포트 · 수신지 포트 · 길이 · 검사합 = 8B)** 이며, `IP`나 `데이터`, `Window Size`는 절대 들어가지 않는다.

## 2. 체크섬(검사합)의 역할을 4번 연속 다르게 착각함

### 처음 생각 (오답)
체크섬의 역할을 물었을 때 4번에 걸쳐 서로 다른 오답을 적었다.
1. "UDP 방식 QUIC 기술 위에서 손상된 패킷을 버리는 QUIC 전용 기술이다."
2. "캡슐화 과정에서 쪼개 보낸 데이터의 **순서를 보고 맞추는 것**이다."
3. "이 송신이 **알맞은 곳(목적지)으로 전달되었는가**를 확인하는 것이다."
4. "헤더의 검사합 칸이 스스로 검사해서 버린다."

### 원리
역할별로 담당하는 필드가 명확히 나뉘어 있다.

| 확인하고 싶은 것 | 담당하는 것 |
|---|---|
| 알맞은 컴퓨터·프로그램으로 갔는가? | **IP 주소 · 포트 번호** |
| 쪼개진 조각의 순서가 맞는가? | **TCP 시퀀스 번호(Sequence Number)** |
| 오는 도중에 비트가 깨지지(손상되지) 않았는가? | **체크섬(Checksum, 검사합)** |
| 없어진 패킷을 다시 보내 복구하는가? | **TCP(또는 QUIC) 재전송** |

체크섬은 IP, TCP, UDP 모두에 있는 일반적인 오류 검출 값이다. 보내는 쪽 OS가 합산 후 비트를 뒤집어 적어 보내면, **받는 쪽 OS**가 다시 더해 보고 손상되었으면 **조용히 폐기(버림)** 할 뿐 다시 달라고 요청하지 않는다.

### 깨달음
**체크섬 = 오직 "비트가 깨졌나?"만 검사해서 깨졌으면 버리는 것(검사 O, 복구 X)**. 순서 맞추기(시퀀스 번호)나 목적지 확인(포트·IP), 복구(재전송)와 절대 섞지 않는다.

## 3. UDP 자체의 특징과 QUIC의 특징을 섞어 적음

### 처음 생각 (오답)
- "UDP 전송의 특징을 서술하시오"라는 백지 테스트에서 "Wi-Fi에서 LTE로 바뀔 때 연결 ID를 보고 연결을 유지한다", "순서대로 송수신한다", "스트림으로 나눠 퍼즐 맞추기를 한다"고 적었다.

### 원리
```text
UDP 자체  : 연결 설정 X, 연결 ID X, 순서 보장 X, 스트림 개념 X  (그냥 던지고 끝나는 빈 도로)
QUIC      : UDP라는 빈 도로 위에 구글이 새로 지은 건물 (연결 ID, 독립 스트림, 재전송, TLS를 직접 구현)
```
UDP 자체는 순서를 전혀 맞추지 않고 도착한 순서대로 응용 프로그램에 넘긴다. 스트림 번호로 퍼즐을 맞추고 연결 ID로 경로 이동을 하는 것은 **QUIC(HTTP/3)** 이다.

### 깨달음
**UDP 서술형**에는 **"비연결 · 연도순재흐(연결·도착·순서·재전송·흐름/혼잡 제어) 없음 · 포포길검 8B"** 만 쓰고, QUIC은 마지막 줄에 "HTTP/3의 QUIC이 UDP를 기반으로 동작한다"고 **사용 사례로만** 언급한다.

## 4. 전송 계층과 네트워크 계층이 연결하는 대상 혼동

### 처음 생각 (오답)
"전송 계층이 네트워크 계층과 무엇을 연결하는지 비교하시오"라는 문제에 "전송 계층은 세그먼트·프로그램을 연결하고, 네트워크 계층은 패킷·**라우터들**을 연결한다"라고 답했다.

### 원리
라우터는 중간에서 길을 안내하는 장비일 뿐이다.
- **네트워크 계층(IP)**: 출발지 **호스트(컴퓨터)** 와 목적지 **호스트(컴퓨터)** 를 연결한다.
- **전송 계층(포트)**: 호스트 안에서 실행 중인 출발지 **프로세스(프로그램)** 와 목적지 **프로세스(프로그램)** 를 연결한다.

### 깨달음
**네트워크 계층 = 호스트 ↔ 호스트(IP)**, **전송 계층 = 프로세스 ↔ 프로세스(포트)**.

## 정리

| 착각 | 바로잡은 규칙 |
|---|---|
| UDP 헤더 = 포트·포트·데이터·검사합 | 포트·포트·**전체 길이**·검사합 (8바이트, 데이터는 헤더 밖) |
| 체크섬 = 순서 맞추기 / 목적지 확인 | 체크섬 = 비트 손상 여부 **검사만** (손상 시 폐기, 복구 X) |
| UDP가 연결 ID와 스트림으로 순서 맞춤 | UDP는 순서·연결 없음, 연결 ID·스트림은 **QUIC**의 기능 |
| 네트워크 계층 = 라우터끼리 연결 | 네트워크 계층 = **호스트 간** 연결, 전송 계층 = **프로세스 간** 연결 |
