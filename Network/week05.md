## 1. 전송 계층 vs 네트워크 계층

| 구분 | 네트워크 계층 (3계층) | 전송 계층 (4계층) |
|---|---|---|
| **연결 대상** | **호스트 ↔ 호스트** (컴퓨터 간 전달) | **프로세스 ↔ 프로세스** (응용 프로그램 간 전달) |
| **사용 주소** | **IP 주소** | **포트 번호** |
| **아파트 비유** | 택배 기사가 **몇 동 건물**까지 배달 | 건물 경비실이 **몇 호 우편함(소켓)** 에 넣어줌 |
| **동작 위치** | 양 끝 호스트 + 중간의 모든 **라우터** | 오직 양 끝 **종단 호스트**에서만 동작 |

## 2. 포트 번호(Port) 범위와 주요 포트

한 컴퓨터(단일 IP) 안에서 크롬, 카카오톡, 게임 등 여러 프로그램이 동시에 통신할 때, 도착한 데이터를 **어느 프로세스에 전달할지 구분**하기 위해 16비트(0~65535) 포트 번호를 사용한다.

| 범위 | 분류 | 설명 및 대표 포트 |
|---|---|---|
| **0 ~ 1023** | **잘 알려진 포트 (Well-known)** | 표준 서비스 고정 번호 — HTTP(**80**), HTTPS(**443**), SSH(**22**), Telnet(**23**), FTP(**20/21**), SMTP(**25**), DNS(**53**), DHCP(**67/68**), POP3(**110**), IMAP(**143**) |
| **1024 ~ 49151** | **등록된 포트 (Registered)** | 특정 프로그램용 — MySQL(**3306**), RDP 원격 데스크톱(**3389**), 개발용 웹 서버(**8000, 8080**) |
| **49152 ~ 65535** | **동적 / 임시 포트 (Ephemeral)** | 클라이언트가 새 연결을 만들 때마다 **OS가 비어 있는 번호 중 임시로 할당** (브라우저 재실행 시 바뀜) |

## 3. 다중화(Multiplexing)와 역다중화(Demultiplexing)

```text
[송신 측: 다중화]                             [수신 측: 역다중화]
소켓 A (크롬)   ─┐                           ┌─→ 소켓 A (포트 보고 전달)
소켓 B (카톡)   ─┼─→ [전송 계층: 포트 헤더 부착] ──→ [전송 계층: 포트 헤더 확인] ─┼─→ 소켓 B
소켓 C (게임)   ─┘                           └─→ 소켓 C
```
- **다중화(송신)**: 여러 소켓에서 내려온 데이터에 출발지·목적지 포트 헤더를 붙여 세그먼트로 만들어 네트워크 계층에 넘기는 과정
- **역다중화(수신)**: 도착한 세그먼트의 헤더를 확인하여 알맞은 소켓(프로세스)으로 나눠주는 과정
  - **UDP 소켓 구분 기준 (2-튜플)**: `목적지 IP + 목적지 포트`
  - **TCP 소켓 구분 기준 (4-튜플)**: `출발지 IP + 출발지 포트 + 목적지 IP + 목적지 포트` (같은 443 포트로 접속한 여러 클라이언트를 구분하기 위함)

## 4. 5-튜플 (5-Tuple)
네트워크에서 하나의 **연결(통신 흐름)을 고유하게 식별하는 5가지 정보 묶음**이다.
1. **출발지 IP 주소**
2. **출발지 포트 번호** (클라이언트 임시 포트)
3. **목적지 IP 주소**
4. **목적지 포트 번호** (서버 서비스 포트)
5. **전송 계층 프로토콜** (`TCP` 또는 `UDP`)

## 5. UDP (User Datagram Protocol)의 특징과 헤더 구조
- **비연결 지향**: 사전 연결 설정(3-way handshake)이나 해제 절차 없이 **즉시 데이터 전송**
- **신뢰성 미제공**: 수신 확인(ACK)을 하지 않으므로 **도착 보장, 순서 보장, 재전송, 흐름 제어, 혼잡 제어** 기능이 모두 없다.
- **장점과 사용처**: 확인 왕복 지연이 없고 헤더 오버헤드가 작아 **속도와 실시간성이 중요한 서비스**(**DNS, 실시간 음성·영상 통화, 온라인 게임, 라이브 스트리밍, QUIC 기반**)에 사용한다.

### UDP 헤더 구조 (4칸 × 2바이트 = 8바이트 고정)
```text
 0                  16                  32 (비트)
┌───────────────────┬───────────────────┐
│   송신지 포트      │   수신지 포트      │  ← 어느 프로그램에서 어느 프로그램으로 (각 2B)
├───────────────────┼───────────────────┤
│   전체 길이        │   검사합(체크섬)   │  ← UDP 헤더+데이터 길이 / 비트 손상 검사 (각 2B)
└───────────────────┴───────────────────┘
│            데이터 (페이로드)           │
```

## 6. UDP 체크섬(Checksum, 검사합)의 원리와 역할
- **계산 원리**: 데이터를 16비트 단위로 모두 더하고(자리올림은 끝에 다시 더함) **비트를 모두 반전(1의 보수)** 시켜 체크섬 칸에 넣는다. 수신 측은 받은 데이터와 체크섬을 모두 더해 **비트가 전부 `1`이면 정상**, 하나라도 `0`이 있으면 손상으로 판정한다.
- **체크섬 vs 재전송**:
  - **체크섬**: 전송 도중 비트가 깨졌는지 **오류를 검출(검사)** 할 뿐이며, 손상이 발견되면 해당 패킷을 **그냥 폐기(버림)** 한다.
  - **재전송**: 손실·폐기된 데이터를 다시 보내 **복구**하는 기능으로, UDP에는 없고 **TCP(또는 QUIC)** 에만 있다.

## 7. TCP vs UDP 비교 (6항목: "연·도·흐·오·예·선")

| 비교 항목 | TCP | UDP |
|---|---|---|
| **① 연결 설정** | **연결 지향** (3-way handshake 후 전송) | **비연결 지향** (절차 없이 바로 전송) |
| **② 도착 · 순서 보장** | 보장 (시퀀스 번호, ACK, 재전송) | 보장 안 함 |
| **③ 흐름 · 혼잡 제어** | 있음 (`rwnd`, `cwnd`) | 없음 |
| **④ 오버헤드** | 큼 (헤더 기본 **20B** 이상 + ACK 왕복) | 작음 (헤더 **8B** 고정) |
| **⑤ 대표 사용 예** | 웹(HTTP/1.1, 2), 이메일, 파일 전송, 결제·송금 | DNS, 실시간 통화·화상회의, 온라인 게임, QUIC |
| **⑥ 선택 기준** | **정확성·신뢰성**이 중요할 때 | **속도·실시간성**이 중요할 때 |
