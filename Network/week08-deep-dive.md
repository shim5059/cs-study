# 8주차 Deep Dive · ARP 테이블, STP, 오류 문구에서 헷갈렸던 것

> 개념 요약: [week08.md](week08.md)
>
> 이 문서는 개념 정리가 아니라 **내가 실제로 틀렸던 것 → 처음 생각 → 원리 → 깨달음** 순서로 남긴 기록이다.

---

## 1. ARP 테이블에는 "알아낸 MAC"만 저장된다고 생각함

### 처음 생각 (오답)
`arp -a`를 치면 ARP로 알아낸 **MAC 주소**가 보일 것이라고 답했다.

### 원리
ARP 테이블은 "이 IP의 주인은 이 MAC이다"를 적어 둔 **주소록**이다. 원래 알고 있던 IP와 새로 알아낸 MAC이 **한 쌍**으로 저장된다.
```text
Internet Address    Physical Address     Type
192.168.10.11       0001.4321.aaaa       dynamic
(알고 있던 IP)       (ARP로 알아낸 MAC)    (자동 학습, 시간 지나면 삭제)
```

### 깨달음
ARP는 **IP ↔ MAC 짝을 만드는 과정**이고, ping은 그 짝을 보고 프레임에 MAC을 채운다.

---

## 2. STP가 "다른 프로토콜이 도는 것"을 막는다고 생각함

### 처음 생각 (오답)
주황불이 STP 때문이라는 건 맞혔지만, 이유를 "바로 초록이 되면 ping과 상관없이 도는 프로토콜들이 계속 돌아가기 때문에 STP가 이를 막는다"고 설명했다.

### 원리
STP가 막는 대상은 다른 프로토콜이 아니라 **루프에서 프레임이 영원히 도는 것**이다.
- 스위치를 이중 연결하면 길이 동그랗게 이어지고, 브로드캐스트(ARP 요청 등)가 스위치끼리 계속 돌며 **브로드캐스트 스톰**이 된다.
- IP 패킷은 TTL이 있어 결국 죽지만, **이더넷 프레임에는 TTL이 없다.**
- 그래서 포트가 켜지면 바로 열지 않고 루프가 생기는지 먼저 확인한다 (약 30초).

### 깨달음
**주황 = 루프 검사 중, 초록 = 검사 통과.** 2계층에는 TTL이 없어서 STP가 필요하다.

---

## 3. 게이트웨이 없이 다른 서브넷에 ping하면 "타임아웃"이라고 생각함

### 처음 생각 (오답)
"어디로 나가야 할지 몰라서 오류"라는 이유는 맞혔지만, 오류 이름을 **타임아웃**이라고 답했다.

### 원리
```text
Destination host unreachable → 아예 못 보냄 (출구/경로 없음, 패킷이 PC 밖으로 안 나감)
Request timed out            → 보냈는데 답이 안 옴
```
VLAN 실습의 PC0 → PC3 타임아웃은 후자다. ARP 요청은 나갔지만 같은 VLAN 안에 PC3이 없어서 아무도 답하지 않았다.

### 깨달음
둘 다 "안 된다"로 보이지만 **문구를 읽으면 어디를 의심할지** 정해진다. unreachable이면 설정(게이트웨이·경로), timeout이면 상대 쪽(VLAN·돌아오는 경로).

---

## 정리

| 착각 | 바로잡은 규칙 |
|---|---|
| ARP 테이블 = 알아낸 MAC 목록 | **IP와 MAC의 짝**으로 저장 |
| STP = 다른 프로토콜이 도는 걸 막음 | STP = **루프(브로드캐스트 스톰)** 방지, 이더넷 프레임엔 TTL이 없음 |
| 게이트웨이 없음 → 타임아웃 | 게이트웨이 없음 → **`Destination host unreachable`** |
