## 1. 스태틱 경로의 Network 칸에 PC의 IP를 적음

### 처음 생각 (오답)
R1(오른쪽 라우터)의 스태틱 경로를 채우는 문제에서 Network 칸에 **PC3의 IPv4 주소**를 적었다. (Mask, Next Hop은 맞힘)

### 원리
1. Network에는 PC 한 대가 아니라 **망 전체의 이름(네트워크 주소, 호스트 부분이 0)** 을 적는다.
   ```text
   PC3: 192.168.20.10 AND 255.255.255.0 = 192.168.20.0
   PC4: 192.168.20.11 AND 255.255.255.0 = 192.168.20.0   → 한 줄로 둘 다 처리
   ```
2. R1 입장에서 20망(PC3)은 **자기 포트에 직접 붙어 있어** 적을 필요가 없다. R1이 알아야 하는 곳은 **반대편 10망**이다.
   ```text
   R1: Network 192.168.10.0 / Mask 255.255.255.0 / Next Hop 192.168.30.1
   ```

### 깨달음
Network = **가야 할 반대편 망 주소(.0)**, 직접 연결된 망은 안 적는다. R0과 R1의 설정은 서로 거울 모양이다.

## 2. ACK를 기다리는 시간을 "TTL"이라고 부름 / 빠른 재전송과 섞음

### 처음 생각 (오답)
ACK가 안 오면 어떻게 하냐는 질문에 "ACK가 **3번** 안 오면 빠른 재전송, 임의의 **TTL**을 계산하여 기준을 세우고 그 시간 동안 안 오면 타임아웃 재전송"이라고 답했다.

### 원리
```text
타임아웃 (타이머) → ACK를 기다리는 시간. 보통 RTT보다 조금 길게 잡음
TTL              → IP 패킷이 라우터를 몇 번 더 지날 수 있는지 (홉 수)
빠른 재전송       → TCP(3장). 같은 번호의 ACK가 "3번 중복"으로 오면 타임아웃 전에 재전송
링크 계층 ARQ     → 타임아웃만 쓰는 단순한 방식
```

### 깨달음
**시간 = 타임아웃, 라우터 횟수 = TTL.** 빠른 재전송은 "ACK가 안 오는 것"이 아니라 **"중복 ACK 3번"** 이 조건이다.

## 3. 도메인 개수를 장치 수로 셈

### 처음 생각 (오답)
스위치 1대에 PC 4대(전이중)를 연결했을 때:
- 충돌 도메인: "PC1~PC4가 동시에 보내면 다 충돌 날 수 있다"
- 브로드캐스트 도메인: "전체가 4개니까 **4개**"

### 원리
- 도메인 개수 = **따로 나뉜 범위의 개수**다. 장치 수가 아니다.
- 스위치는 포트마다 **전용선**이라 충돌은 그 한 줄 안에서만 날 수 있다 → 충돌 도메인 **4개**. (모두 충돌하는 건 **허브**일 때 → 1개)
- 브로드캐스트는 스위치를 지나 4대 모두에게 닿는다 → 한 범위 안 → 브로드캐스트 도메인 **1개**.

| 구성 | 충돌 | 브로드캐스트 |
|---|---|---|
| 허브 + PC 4대 | 1 | 1 |
| 스위치 + PC 4대 | 4 | 1 |

### 깨달음
**충돌 도메인은 스위치가, 브로드캐스트 도메인은 라우터·VLAN이 쪼갠다.**

## 4. VLAN 3개인데 "한 스위치 + 같은 서브넷"이라 브로드캐스트 도메인 1개라고 생각함

### 처음 생각 (오답)
스위치 1대에 VLAN 3개(STAFF, GUEST, MANAGER)를 만들었을 때 "결국 한 스위치에 종속되어 있고 서브넷 주소가 같기 때문에 1개"라고 답했다.

### 원리
- 스위치가 한 대여도 VLAN으로 나누면 **논리적으로 별개의 스위치 3대**처럼 동작한다 → 브로드캐스트 도메인 **3개**.
- 서브넷은 3계층(IP) 설정이고, 브로드캐스트 도메인은 2계층 프레임이 퍼지는 범위다. **별개**다. 보통 VLAN 하나에 서브넷 하나를 짝지어 쓸 뿐이다.
- 실습의 PC0 → PC3 타임아웃: ARP 요청이 VLAN 경계를 못 넘어 PC3까지 닿지 않음 → VLAN 간 통신에는 **라우터**가 필요.

### 깨달음
**VLAN 개수 = 브로드캐스트 도메인 개수.** 서브넷이 같아도 VLAN이 다르면 서로 못 닿는다.

## 5. 이더넷 프레임 칸 순서를 기억하지 못함 (시험 전 재확인)

### 처음 생각
프레임 구조를 적어 보라는 질문에 "기억 안 남"이라고 답했다. SFD가 "다음부터 진짜 프레임이라는 표시"라는 것은 맞혔다.

### 원리
```text
프리앰블 → SFD → 목적지 MAC → 출발지 MAC → 이더타입 → 페이로드 → FCS
"전화 받으세요" → "지금부터 말합니다" → 누구에게 → 누구로부터 → 뭐가 들었나 → 내용물 → 확인 도장
```

### 깨달음
**받는 사람(목적지 MAC)이 먼저.** 앞 둘은 신호 정리, 가운데 셋은 헤더, 맨 뒤 FCS는 트레일러.

## 정리

| 착각 | 바로잡은 규칙 |
|---|---|
| 스태틱 Network 칸 = PC의 IP | **반대편 망 주소(.0)**, 직접 연결된 망은 안 적음 |
| ACK 대기 시간 = TTL | ACK 대기 = **타임아웃**, TTL = 라우터 홉 수 |
| 빠른 재전송 = ACK 3번 안 옴 | 빠른 재전송(TCP) = **중복 ACK 3번** |
| 스위치 + PC 4대: 충돌 1 / 브로드캐스트 4 | 충돌 **4** / 브로드캐스트 **1** (도메인 = 범위의 수) |
| VLAN 3개여도 한 스위치·같은 서브넷이면 1 | VLAN 3개 = 브로드캐스트 도메인 **3** |
| 프레임 칸 순서 기억 못 함 | 프리앰블 → SFD → **목적지** → 출발지 → 이더타입 → 페이로드 → FCS |
