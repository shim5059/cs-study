## 1. 라우터 2대 스태틱 라우팅 (패킷트레이서)

라우터가 "이 목적지는 어느 문으로 내보내지?"를 정하는 대응표를 **사람이 직접 적어 주는 것**이 스태틱(static, 고정) 라우팅이다.

### 구성

```text
[PC1 .10, PC2 .11]--SW0--(10.1) R0 (30.1)────(30.2) R1 (20.1)--SW1--[PC3 .10, PC4 .11]
      192.168.10.0/24              192.168.30.0/24              192.168.20.0/24
         (10망)                       (30망, 라우터 사이)              (20망)
```

| 장치 | 포트 | IP |
|---|---|---|
| R0 | 왼쪽 (10망) | 192.168.10.1 |
| R0 | 가운데 (30망) | 192.168.30.1 |
| R1 | 가운데 (30망) | 192.168.30.2 |
| R1 | 오른쪽 (20망) | 192.168.20.1 |
| PC1·PC2 | 게이트웨이 | 192.168.10.1 |
| PC3·PC4 | 게이트웨이 | 192.168.20.1 |

- 망은 **3개**: 왼쪽 LAN, 라우터 사이 연결선, 오른쪽 LAN.
- 라우터는 **포트마다 IP가 따로** 있다 (입구·출구). 포트 Status가 **On**인지 확인.
- 왼쪽/오른쪽 PC의 게이트웨이가 다른 이유: 각자 **나가는 첫 문(자기 쪽 라우터 포트)** 이 다르기 때문.

### 스태틱 경로 (Config → Routing → Static)

| 칸 | 뜻 | R0 | R1 |
|---|---|---|---|
| Network | **최종 목적지 망**(호스트 부분이 0) | 192.168.20.0 | 192.168.10.0 |
| Mask | 그 망의 크기 | 255.255.255.0 | 255.255.255.0 |
| Next Hop | **같은 선에 붙은 상대 라우터 포트** | 192.168.30.2 | 192.168.30.1 |

- **Network에는 PC 한 대의 IP가 아니라 망 주소**를 적는다. 라우터는 목적지 IP AND 마스크로 망 주소를 만들어 비교하므로, `20.10`(PC3)과 `20.11`(PC4) 모두 `20.0` 한 줄로 처리된다.
- **직접 연결된 망은 적지 않는다.** 포트에 IP와 마스크를 넣는 순간 라우터가 이미 안다. 그래서 각 라우터는 **반대편 망 하나만** 적는다.
- **Next Hop에 자기 포트를 쓰면 안 된다.** 라우터 안에서 맴돌 뿐 다른 라우터로 못 넘어간다. 같은 30망에 있어 바로 ARP로 MAC을 물을 수 있는 상대 포트를 적는다.
- **양쪽 다 적어야** ping이 성공한다. 한쪽만 적으면 요청은 가는데 응답이 못 돌아와 타임아웃.

### PC1 → PC3 흐름

1. PC1: 다른 망 → **게이트웨이(R0 10.1)의 MAC**을 ARP로 물음
2. R0: 표를 보고 R1 30.2로 넘김 (30망 안의 MAC으로 프레임 새로 만듦)
3. R1: 20망은 직접 연결 → PC3 MAC을 ARP로 알아내 전달
4. IP는 끝까지 그대로, **MAC만 홉마다 바뀜**

> 현업: 규모가 크면 OSPF, BGP 같은 **동적 라우팅**이 이 표를 자동으로 채운다.

## 2. 데이터 링크 계층과 MAC 주소

- 3계층이 만든 패킷을 **프레임**으로 감싸 **같은 링크 안의 다음 홉까지** 전달한다.
- **MAC 주소**: 48비트, 16진수 12자리. 앞 절반 = 제조사 식별 번호, 뒤 절반 = 장비 번호.
  - 항상 변경 불가능한 값은 아니다. 소프트웨어로 바꿀 수 있고, 임시 MAC을 쓰는 **MAC 랜덤화**도 있다.

| 종류 | 대상 | 예 |
|---|---|---|
| 유니캐스트 | 1:1 | 특정 PC의 MAC |
| 멀티캐스트 | 1:N (그룹) | 그룹 주소 |
| 브로드캐스트 | 1:N (전부) | `FF:FF:FF:FF:FF:FF` (VLAN 단위로 플러딩) |

## 3. 이더넷 II 프레임 구조

```text
프리앰블 | SFD | 목적지 MAC | 출발지 MAC | 이더타입 | 페이로드 | FCS
```

| 칸 | 역할 | 외우기 |
|---|---|---|
| 프리앰블 | 송수신 동기 (`10101010` 반복) | "전화 받으세요" |
| SFD | **여기서부터 진짜 프레임** (`10101011`) | "지금부터 말합니다" |
| 목적지 MAC | 받는 장치 (6B) | 누구에게 (**받는 사람이 먼저**) |
| 출발지 MAC | 보내는 장치 (6B) | 누구로부터 |
| 이더타입 | 안에 든 내용 종류 (ARP, IP 등) | 무엇이 들었나 |
| 페이로드 | 위 계층 데이터(패킷) | 내용물 |
| FCS | 오류 검출 값 (트레일러) | 확인 도장 |

- SFD가 없으면 프리앰블이 어디서 끝나는지 몰라 비트를 어긋나게 읽고 목적지를 잘못 읽는다.

## 4. 오류 검출(FCS/CRC)과 재전송(ARQ)

### CRC와 FCS
- **CRC** = 검사값 계산 방법, **FCS** = 그 값이 들어가는 프레임 칸.
```text
송신: 데이터 → CRC 계산 → FCS 첨부
수신: 받은 데이터로 CRC 재계산 → FCS와 비교 → 일치: 상위 계층 전달 / 불일치: 프레임 폐기
```
- 수업 예시(나머지 방식): 데이터 `1011`(11), 약속된 수 3 → 나머지 2를 FCS로. 깨져서 `1001`(9)이 되면 나머지 0 ≠ 2 → 폐기. (실제 CRC는 2진 다항식 나눗셈, 32비트)

### ARQ
```text
송신 → DATA[1] → 수신
송신 ← ACK[1]  ← 수신
송신 → DATA[2] → 수신   (유실)
  ---- 타임아웃 ----
송신 → DATA[2] → 수신   (같은 프레임 재전송)
송신 ← ACK[2]  ← 수신
```
- 일정 시간(**타임아웃**) 안에 ACK가 없으면 같은 프레임을 재전송. 기다리는 시간은 보통 왕복 시간(RTT)보다 조금 길게.
- 재전송이 많아지면 링크 효율이 떨어진다. 무선이 느리게 느껴지는 이유.

> 현업: 스위치 포트의 **CRC error 카운터**가 계속 늘면 케이블·접촉 불량, 노이즈를 먼저 의심한다.

## 5. 허브와 스위치, 충돌 도메인과 브로드캐스트 도메인

| | 허브 | 스위치 |
|---|---|---|
| 동작 | 들어온 신호를 **모든 포트**로 재전송 | **목적지 MAC**을 보고 필요한 포트로만 |
| 충돌 도메인 | 전체 공유 | 포트별 **분리** |

### 스위치의 MAC 주소 테이블
1. **학습**: 들어온 프레임의 출발지 MAC + 들어온 포트를 기록
2. **포워딩/필터링**: 목적지 MAC이 표에 있으면 그 포트로만
3. **플러딩**: 표에 없거나 브로드캐스트면 받은 포트 제외 모든 포트로
- 오래 안 쓰인 항목은 일정 시간 뒤 삭제 (늘 갱신)

### 두 도메인
- **충돌 도메인**: 동시에 보내면 충돌할 수 있는 범위
- **브로드캐스트 도메인**: 브로드캐스트 프레임이 퍼지는 범위
- 도메인 개수 = **범위의 개수** (장치 수가 아님)

| 구성 | 충돌 도메인 | 브로드캐스트 도메인 |
|---|---|---|
| 허브 + PC 4대 | 1 | 1 |
| 스위치 + PC 4대 | 4 | 1 |
| 스위치 1대 + VLAN 3개 | (포트 수) | **3** |

- 충돌 도메인은 **스위치**가 쪼갠다. 브로드캐스트 도메인은 **라우터 또는 VLAN**이 쪼갠다.
- VLAN은 서브넷(3계층 IP)과 **별개**로 2계층에서 브로드캐스트 범위를 나눈다.

## 6. STP와 RSTP

- 스위치 이중 연결로 생기는 루프를 일부 포트를 막아 **트리 구조**로 만든다. (트리에는 루프가 없다)
1. 스위치끼리 **BPDU**를 주기적으로 교환 (약 2초)
2. 기준점인 **루트 브릿지**를 선출 (실제로는 Bridge ID = 우선순위 + MAC이 가장 낮은 스위치)
3. 각 스위치는 루트까지 가는 **경로 비용**이 가장 작은 포트를 고름
4. 루프를 만드는 포트는 **블로킹**, 나머지는 **포워딩**
- 막힌 선 때문에 옆 가지로 갈 때도 부모(위쪽)를 거쳐 돈다. ("사촌에게 가려면 부모를 거쳐야")
- **RSTP**: STP 개선판. 하는 일은 같고 수렴 속도가 빠름.

## 7. CSMA/CD와 CSMA/CA

| 약자 | 뜻 |
|---|---|
| CS (Carrier Sense) | 보내기 전에 선이 비었는지 듣는다 |
| MA (Multiple Access) | 여러 대가 같은 매체를 쓴다 |
| CD (Collision **Detection**) | 충돌을 **감지**하면 멈추고 잠시 쉬었다 재전송 |
| CA (Collision **Avoidance**) | 충돌을 **회피**하려고 미리 기다림 |

| | CSMA/CD | CSMA/CA |
|---|---|---|
| 환경 | 유선 (옛 방식, 허브 시절) | 무선 (Wi-Fi 802.11) |
| 이유 | 스위치·전이중으로 지금은 거의 안 씀 | 무선은 충돌을 **감지하기 어려워** 미리 피함 |

- 무선은 **AP(액세스 포인트)** 가 중간에서 교통정리. 서로 못 듣는 두 단말 사이를 AP가 양쪽 다 듣고 조율 (RTS/CTS). 보낸 뒤 ACK로 확인.

## 8. VLAN, 802.1Q 태깅, 트렁킹

- **VLAN**: 물리적 LAN을 논리적 그룹으로 나눈 가상 LAN. (학년 전체 = LAN, 1반·2반 = VLAN)
- **802.1Q 태그**: 출발지 MAC과 이더타입 사이에 4바이트 삽입. VLAN ID 12비트 → **1~4094**.
```text
프리앰블 | SFD | 목적지 MAC | 출발지 MAC | [802.1Q 태그] | 이더타입 | 페이로드 | FCS
```

| | 액세스 포트 | 트렁크 포트 |
|---|---|---|
| 연결 | PC 등 단말 | 스위치 ↔ 스위치 (또는 라우터) |
| VLAN | 하나 | 여러 개 |
| 태그 | **없음** (PC는 태그를 모름, 내보내기 전 제거) | **있음** (VLAN 구분 필요) |

- **VLAN 트렁킹**: 여러 VLAN 트래픽을 **하나의 물리 링크**로 묶어 전달. 양쪽 포트를 **모두 트렁크**로 맞춰야 한다.

## 9. PoE와 VXLAN

- **PoE (Power over Ethernet)**: 랜선 하나로 **데이터 + 전력**. AP, CCTV, IP 전화처럼 콘센트 없는 곳에 유용. 스위치 총 전력에 한도가 있다.
- **VXLAN**: VLAN 프레임을 **IP(UDP) 패킷으로 감싸서** 라우터를 넘어 먼 지역까지 같은 LAN처럼 연결. 식별자(VNI) 24비트로 약 1,600만 개 (VLAN 4094개 한계 해소). 데이터센터·클라우드에서 사용.
