## 1. `new int[3]`의 3은 "마지막 번호"가 아니라 "개수"

### 처음 생각 (오답)
길이 3인 배열 `{10, 20, 30}`에서 `arr[3]`도 정상이라고 봤다. (한 번 고쳤는데 시험 대비 중에 **다시** 틀렸다)

### 원리
```
new int[3]  →  칸 3개

 인덱스:   [0]   [1]   [2]    [3]
          ┌────┬────┬────┐
 값:      │ 10 │ 20 │ 30 │     ✗ 없는 칸
          └────┴────┴────┘
```
번호는 `0`부터 `length - 1`까지다.

```java
int[] arr = {10, 20, 30};
System.out.println(arr[2]);   // 30
System.out.println(arr[3]);   // 컴파일 OK, 실행하면 ArrayIndexOutOfBoundsException
```

### 깨달음
- 칸 개수 = `length`, 마지막 번호 = `length - 1`
- 컴파일러는 값을 계산하지 않으니 `arr[3]`은 **컴파일은 통과**하고 **실행 중**에 터진다

## 2. for-each문의 변수는 "복사본"

### 처음 생각 (오답)
for-each문 안에서 변수 값을 바꾸면 배열도 바뀐다고 생각했다.

### 원리
```java
int[] a = {1, 2, 3};
for (int x : a) {
    x = x * 10;          // x는 칸의 값을 복사한 별개의 변수
}
System.out.println(Arrays.toString(a));   // [1, 2, 3] 그대로
```
```
a[0] = 1  ──복사──▶  x = 1  →  x = 10   (a[0]은 그대로 1)
```

배열을 바꾸려면 인덱스로 직접 접근해야 한다.
```java
for (int i = 0; i < a.length; i++) {
    a[i] = a[i] * 10;    // [10, 20, 30]
}
```

### 깨달음
for-each문은 **읽기 전용**으로 생각한다.

## 3. `Arrays` 메서드의 반환값

### 처음 생각 (오답)
- `Arrays.copyOf(a, 5)`의 5를 "5번 칸까지 복사"로 읽었다.
- `Arrays.sort(a)`가 정렬된 새 배열을 돌려준다고 생각했다.

### 원리
```java
int[] a = {3, 1, 2};

int[] b = Arrays.copyOf(a, 5);   // 새 배열의 "길이"가 5 → [3, 1, 2, 0, 0]
Arrays.sort(a);                  // 반환값 없음(void), a 자체가 [1, 2, 3]으로 바뀜
// int[] c = Arrays.sort(a);     // 컴파일 에러: void는 대입할 수 없음
```

| 메서드 | 반환 | 원본 |
|---|---|---|
| `copyOf(a, n)` | **새 배열** (길이 n) | 그대로 |
| `sort(a)` | 없음 (void) | **바뀜** |
| `fill(a, v)` | 없음 (void) | **바뀜** |

### 깨달음
메서드를 볼 때 **반환값이 있는지, 원본을 바꾸는지**를 따로 확인한다.

## 4. 배열 뒤집기: 왜 `length - 1 - i`이고 왜 `length / 2`번인가

```java
int[] a = {1, 2, 3, 4, 5};
for (int i = 0; i < a.length / 2; i++) {
    int tmp = a[i];
    a[i] = a[a.length - 1 - i];
    a[a.length - 1 - i] = tmp;
}
// [5, 4, 3, 2, 1]
```
```
i=0:  a[0] ↔ a[4]
i=1:  a[1] ↔ a[3]
(가운데 a[2]는 그대로)
```
- `length - 1 - i`: 앞에서 i번째의 **반대편** 번호
- `length / 2`: 끝까지 돌면 이미 바꾼 쌍을 **다시 바꿔서** 원래대로 돌아온다

## 5. 2차원 배열의 `length`

### 처음 생각 (오답)
`m.length`가 전체 칸 수라고 생각했다.

### 원리
2차원 배열은 **배열을 담은 배열**이다.
```java
int[][] m = { {1, 2, 3}, {4, 5, 6} };
```
```
m ──▶ [ ● , ● ]          m.length    = 2  (행 수)
        │    │
        ▼    ▼
   [1,2,3]  [4,5,6]      m[0].length = 3  (0번 행의 칸 수)
```
그래서 안쪽 반복 조건은 `j < m[i].length`라고 쓴다.

## 6. `=`는 붙이기가 아니라 "갈아끼우기"

### 처음 생각 (오답)
`b = a`를 하면 a의 값이 b에 **복사되어 따로** 존재한다고 생각했다.

### 원리
```java
int x = 5;
int y = x;     // 기본형: 값 복사
y = 10;        // x는 5 그대로

int[] a = {1, 2, 3};
int[] b = a;   // 참조형: 주소 복사 → 같은 배열
b[0] = 99;     // a[0]도 99
```
```
기본형                  참조형
x [5]   y [10]          a ──┐
(따로따로)                   ├──▶ [99, 2, 3]
                        b ──┘
```
- `b[0] = 99` (대괄호 있음) → 배열의 **내용**을 바꿈
- `b = c` (대괄호 없음) → b가 가리키는 **배열 자체**를 바꿈

## 7. 2차원 배열의 `clone()`은 얕은 복사

### 처음 생각 (오답)
서술형에서 2차원 `clone()`을 "**한 줄만 복사**된다"고 설명했다.

### 원리
`clone()`은 **바깥 배열만** 새로 만든다. 그 안의 칸에는 행의 **주소**가 들어 있으니 주소만 복사된다.

```java
int[][] m = { {1, 2}, {3, 4} };
int[][] c = m.clone();
c[0][0] = 99;
System.out.println(m[0][0]);   // 99 (행을 공유)
System.out.println(m == c);    // false (바깥 배열은 다름)
```
```
m ──▶ [ ● , ● ]
        │    │
        ▼    ▼
     [99,2] [3,4]     ← 행은 하나뿐 (공유)
        ▲    ▲
        │    │
c ──▶ [ ● , ● ]       ← 바깥 배열만 새로 생김
```

### 깨달음
얕은 복사 = **껍데기만 새로, 안쪽은 공유**. 행까지 따로 만들려면 행마다 `clone()`해야 한다(깊은 복사).

## 정리

| 착각 | 바로잡은 규칙 |
|---|---|
| `arr[3]` 정상 | 번호는 `0 ~ length-1`, 없는 칸은 **실행 중** 예외 |
| for-each로 배열 수정 | 변수는 **복사본** |
| copyOf의 n = 마지막 번호 | n = **새 길이** |
| sort가 새 배열 반환 | **void**, 원본 변경 |
| `m.length` = 전체 칸 | **행 수** |
| 2차원 clone = 한 줄 복사 | 바깥만 새로, **행은 공유** (얕은 복사) |
