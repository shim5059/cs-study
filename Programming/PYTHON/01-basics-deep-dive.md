## 1. for문이 끝나면 줄이 바뀐다고 생각했다

### 처음 생각 (오답)
```python
for i in range(1, 4):
    print(i, end="/")
print("끝")
```
내 답: `1/2/3/` 다음 줄에 `끝` (정답: `1/2/3/끝`)

`range(1, 4)`가 1, 2, 3인 건 맞혔다. 그런데 **반복이 끝나는 순간 줄이 바뀐다**고 생각했다.

### 원리
줄바꿈은 for문이 만드는 게 아니라 **print가 끝에 붙이는 문자**다. `end="/"`가 그 줄바꿈을 `/`로 바꿔 끼웠으니, 이 프로그램에서 줄바꿈은 마지막 `print("끝")` 때 한 번뿐이다.

| 순서 | 실행 | 화면 (커서 `▌`) |
|---|---|---|
| 1 | `print(1, end="/")` | `1/▌` |
| 2 | `print(2, end="/")` | `1/2/▌` |
| 3 | `print(3, end="/")` | `1/2/3/▌` |
| 4 | for문 종료 | `1/2/3/▌` ← 아무것도 출력 안 함 |
| 5 | `print("끝")` | `1/2/3/끝` 후 다음 줄 |

커서를 다음 줄로 옮기는 건 **줄바꿈 문자뿐**이다. Java로 치면 `System.out.print(i + "/")` 세 번 뒤에 `println("끝")`을 한 것과 같다.

### 깨달음
반복문의 시작·끝은 출력과 상관없다. **출력은 print가 쓴 문자만** 따라가면 된다.

## 2. 서로 다른 print 사이에 공백이 생긴다고 생각했다

### 처음 생각 (오답)
```python
def f():
    print("X", end="")
    return "Y"

print(f())
```
내 답: `X Y` (정답: `XY`)

X와 Y가 둘 다 나오는 건 맞혔지만 사이에 공백을 넣었다.

### 원리
공백은 **한 print 안에서 쉼표로 여러 값을 넘길 때만** 생긴다 (`sep`). 여기서 X와 Y는 **서로 다른 두 print**가 출력했고, 첫 print가 `end=""`로 끝냈다.

| 코드 | 결과 |
|---|---|
| `print("X", "Y")` | `X Y` (한 print, 쉼표 → 공백) |
| `print("X", end="")` 다음 `print("Y")` | `XY` (두 print, end="" → 붙음) |
| `print("X")` 다음 `print("Y")` | `X` 줄바꿈 `Y` |

### 깨달음
실행 결과는 **공백 하나도 점수**다. 다 쓰고 나서 "각 print의 `end`가 뭐였지?"를 다시 확인한다.

## 정리

| 착각 | 바로잡은 규칙 |
|---|---|
| for문이 끝나면 줄이 바뀐다 | 줄바꿈은 **print의 `end`**만 결정 |
| 다른 print 사이엔 공백이 생긴다 | 공백은 **한 print 안의 쉼표(`sep`)**에서만 |

## 3. 오류 줄 찾기: Java 습관 (2026-11-13)

| 회차 | 코드 | 내 답 | 정답 |
|---|---|---|---|
| 1회 | `for i in range(1, n + 1)` (콜론 없음) | 7번 줄 | **3번 줄** |
| 2회 | `else if s >= 80:` | 모름 | **4번 줄** (`elif`) |

두 번 다 실행 결과는 맞혔다. 오류 찾기는 **Python이 Java와 다른 곳**부터 본다.

| Java | Python |
|---|---|
| `else if` | `elif` |
| `{ }` | 들여쓰기 + 줄 끝 `:` (`for`, `if`, `elif`, `else`, `def`, `class`, `while`) |
| `true` / `&&` / `i++` | `True` / `and` / `i += 1` |

## 4. `_`를 오류로 봤다: 진짜 오류는 `return` 들여쓰기 (2026-11-14)

```python
def fib(n) :
    result = [ ]
    x, y = 1, 1
    for _ in range(n):
        result.append(x)
        x, y = y, x+y
return result            # ← def와 같은 칸

count = 7
print(fib(count)[-1])
```
`for _ in range(n)`의 `_`가 오류라고 생각했다. `_`는 "값은 안 쓰고 횟수만 필요할 때" 쓰는 **평범한 변수 이름**이다.

진짜 오류는 `return`이 함수 **밖**(맨 앞 칸)에 있는 것 → `SyntaxError: 'return' outside function`. `for`와 같은 칸(4칸)으로 들여쓰면 `[1, 1, 2, 3, 5, 8, 13]` → **13**. 8칸으로 넣으면 for 안이라 첫 회차에 바로 반환돼 1이 나온다.

## 5. range 끝값 하나를 더 뺐다 (2026-11-14)

```python
result = [x ** 2 for x in range(1, 6)]
print(sum(result))
```
내 답 `30` (1 + 4 + 9 + 16) → 정답 **`55`** (25까지). `range(1, 6)`은 1~5. 개수 = 6 − 1 = 5개를 먼저 세면 빠뜨리지 않는다.

---

## 정리 (추가)

| 착각 | 바로잡은 규칙 |
|---|---|
| `_`는 문법 오류 | 횟수만 필요할 때 쓰는 변수 이름 |
| `return` 위치는 상관없음 | 들여쓰기 = 블록. 함수 안, 그리고 for 밖인지 확인 |
| `range(1, 6)`은 1~4 | 끝값 **하나만** 빠짐, 개수 = 끝 − 시작 |
