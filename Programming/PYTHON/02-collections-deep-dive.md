## 1. 피보나치 결과를 16으로 썼다 (예시문제 5번)

### 처음 생각 (오답)
```python
def fibonacci(n):
    seq = []
    a, b = 1, 1
    for _ in range(n):
        seq.append(a)
        a, b = b, a + b
    return seq

terms = 6
print(fibonacci(terms)[-1])
```
내 답: `16` (정답: `8`)

위 코드는 오류를 고친 뒤의 모습이다. 오류 줄(4번)은 맞혔지만, 결과는 근거 없이 계산했다.

### 원리
| 단계 | 의미 |
|---|---|
| `range(6)` | 0~5, **6번** 반복 → seq에 6개가 들어감 |
| seq | `[1, 1, 2, 3, 5, 8]` |
| `[-1]` | **마지막** 원소 → `8` |

`a, b = b, a + b`는 오른쪽을 **먼저 전부 계산한 뒤** 한꺼번에 넣는다 (03 참고).

### 깨달음
`range(n)` = n번, `[-1]` = 마지막. Java에는 음수 인덱스가 없어서 낯설었다.

## 2. `items()`를 몰랐다 (예시문제 4번)

### 처음 생각
```python
def test(dict, x):
    return [k for k, v in dict.( ① ) if v == x]
```
빈칸이 뭔지 몰랐다. 컴프리헨션 자체도 처음 봤다.

### 원리
| 메서드 | 꺼내는 것 |
|---|---|
| `keys()` | 키만 |
| `values()` | 값만 |
| `items()` | **(키, 값) 짝** |

`for` 뒤에 변수가 **두 개(`k, v`)**면 짝을 꺼내는 것이므로 `items()`다.

### 깨달음
빈칸 문제는 **for 뒤 변수 개수**를 먼저 본다.

## 3. 딕셔너리 `in`이 값도 찾는다고 생각했다

### 처음 생각 (오답)
```python
d = {'a': 3, 'b': 5}
d['c'] = 7
d['a'] = 10
print(d.get('b', 0), d.get('z', 0), len(d), 'c' in d, 7 in d)
```
내 답: `5 0 3 True True` (정답: `5 0 3 True False`)

`get`, `len`, 덮어쓰기는 맞혔다. 값 7이 'c' 칸에 있으니 `7 in d`도 True라고 봤다.

### 원리
딕셔너리의 `in`은 **키만** 검사한다. 우편함으로 치면 **호수판(키)만 훑고 편지(값)는 열어보지 않는다.**

| 호수판(키) | a | b | c |
|---|---|---|---|
| 우편물(값) | 10 | 5 | 7 |

```python
d = {'a': 10, 'b': 5, 'c': 7}
print(7 in d)             # False (키 검사)
print(7 in d.values())    # True  (값 검사)
print(7 in [10, 5, 7])    # True  (리스트는 원소 검사)
```

### 확인 문제 (맞힘)
```python
d = {1: 'x', 'x': 2, 3: 1}
cnt = 0
for k in d:
    if k in d.values():
        cnt += 1
print(cnt, 1 in d, 'x' in d, 2 in d)
# 2 True True False
```

### 깨달음
`in d` = Java `containsKey`, `in d.values()` = `containsValue`.

## 4. for + append가 원소를 뒤로 옮긴다고 생각했다

### 처음 생각 (오답)
```python
r = []
for x in range(5):
    if x % 2 == 0:
        r.append(x * 10)
```
이걸 보고 "만약 r이 아니라 반복 중인 리스트 `[0, 1, 2, 3, 4]`에 append하면, x = 0일 때 `[1, 2, 3, 4, 0]`이 되는 것 아니냐"고 생각했다.

### 원리
- `for x in a`는 칸을 **읽기만** 한다 (값을 x에 복사)
- `append`는 **기존 칸을 그대로 두고** 맨 뒤에 칸을 하나 더 붙인다
- 원본에서 빠지는 건 `pop`, `remove`뿐

```python
a = [0, 1, 2, 3, 4]
for x in a[:]:              # 복사본을 돌림
    if x % 2 == 0:
        a.append(x * 10)
print(a)                    # [0, 1, 2, 3, 4, 0, 20, 40]
```
| x | 짝수? | 실행 후 a |
|---|---|---|
| 0 | ✓ | `[0, 1, 2, 3, 4, 0]` |
| 1 | ✗ | 그대로 |
| 2 | ✓ | `[0, 1, 2, 3, 4, 0, 20]` |
| 3 | ✗ | 그대로 |
| 4 | ✓ | `[0, 1, 2, 3, 4, 0, 20, 40]` |

내가 상상한 `[1, 2, 3, 4, 0]`은 **맨 앞을 빼서 뒤에 붙인** 모양이다.
```python
a = [0, 1, 2, 3, 4]
a.append(a.pop(0))
print(a)                    # [1, 2, 3, 4, 0]
```
복사본 없이 `for x in a:`로 돌면 새로 붙인 0, 20, 40도 반복 대상이 되어 끝나지 않는다.

### 깨달음
"for문이 원소를 **꺼낸다**"의 꺼낸다를 `pop`처럼 **빼낸다**로 받아들였던 것이 원인이었다. for는 읽기만 한다.

## 5. split 후 원본이 바뀌는지

```python
s = "a,b,c,b"
parts = s.split(",")
r = [p.upper() for p in parts if p != "b"]
print(s, parts, r)
# a,b,c,b ['a', 'b', 'c', 'b'] ['A', 'C']
```
s를 `abcb`라고 생각했는데, 문자열 메서드는 원본을 바꾸지 않으므로 **쉼표까지 그대로** `"a,b,c,b"`다.

## 정리

| 착각 | 바로잡은 규칙 |
|---|---|
| `[-1]`, `range(6)`을 감으로 | `[-1]` = 마지막, `range(n)` = n번 |
| 빈칸에 뭘 넣을지 모름 | for 뒤 변수 2개면 `items()` |
| `in d`가 값도 찾음 | `in d`는 **키만** |
| for + append가 원소를 옮김 | for는 읽기, append는 붙이기, 빼기는 pop·remove |
| split하면 원본이 바뀜 | 문자열 메서드는 **새 값을 반환**, 원본 그대로 |
